# Spec: Projects CRUD

**Статус:** Draft
**Дата:** 2026-08-07
**Связанные:** [ADR-011](../../../../docs/adr/011-authorization-acl.md), [RFC-001](../../../../docs/rfc/001-api-contract.md), issue #27

## Цель

Бэкенд для проектов: создать / читать / переименовать / удалить. Проект —
единица доступа ([ADR-011](../../../../docs/adr/011-authorization-acl.md)),
страницы живут внутри (Pages — отдельная задача).

Дополнение о роли входит в scope этой спецификации как отдельная
prerequisite-задача до #136, вне #135; номер отдельной issue пока неизвестен.

## Вне scope

- Управление участниками (инвайты, смена роли, удаление участника) — отдельная задача
- Pages CRUD, вложенность страниц
- Публикация, восстановление из корзины (только пометка удаления)
- Мутационный UI, новые capabilities, отдельный эндпоинт роли и изменения ACL
  в рамках дополнения о роли

## Контракт

ts-rest контракт в `@noto/shared`. Единый shape ошибок `{ code, message, details? }`
([RFC-001](../../../../docs/rfc/001-api-contract.md)).

| Метод  | Путь                   | Кто                              | Успех                |
| ------ | ---------------------- | -------------------------------- | -------------------- |
| POST   | `/projects`            | любой авторизованный (→ `owner`) | `201 { project }`    |
| GET    | `/projects`            | участник                         | `200 { projects[] }` |
| GET    | `/projects/:projectId` | участник (любая роль)            | `200 { project }`    |
| PATCH  | `/projects/:projectId` | `editor`+                        | `200 { project }`    |
| DELETE | `/projects/:projectId` | `owner`                          | `204`                |

Коды ошибок: `UNAUTHORIZED` 401, `FORBIDDEN` 403 (новый код), `NOT_FOUND` 404,
`VALIDATION_ERROR` 400.

### Дополнение: роль текущего пользователя в Project (до #136)

**Статус дополнения:** контракт и тесты согласованы человеком; независимые
SPEC-, TEST- и CODE-review — APPROVE, в CODE-review нет BLOCKER/HIGH.
Проверки пройдены: API unit — 45, Projects e2e — 41, полный API e2e — 311,
web — 316 тестов; build, typecheck и lint shared/API/web — PASS.
Финальная приёмка реализации человеком ожидается; закрытие задачи не заявляется.

Остаются follow-up из CODE-review: unit-проверка ветки отсутствующей роли
в контексте guard и исключение внутреннего имени класса из сообщения `500`
в этой редкой ветке. В текущем проходе они не исправляются.

Источник требования — [спецификация календаря, «Роль пользователя»](../../../web/src/entities/calendar-entry/calendar.spec.md#роль-пользователя).
[ADR-011 §6](../../../../docs/adr/011-authorization-acl.md#6-роль-в-dto-страницы)
определяет роль в DTO страницы как проекцию для UI, не заменяющую серверную
авторизацию; настоящее дополнение расширяет Project, а не приписывает это
требование существующему ADR.

Публичный `Project` сохраняет `id`, `name`, `createdAt`, `updatedAt` и получает
обязательное поле `currentUserRole`: только `owner | editor | viewer`, без
`null`, значения по умолчанию или необязательности. Это единое представление
для каждого элемента `GET /projects`, а также для `project` в ответах
`GET /projects/:projectId`, `POST /projects` и `PATCH /projects/:projectId`.
Статусы, обёртки ответов и контракт `DELETE` не меняются.

Поле вычисляется сервером из `ProjectMember` текущего аутентифицированного
пользователя в соответствующем проекте, не задаётся входными данными клиента.
Тела create/update по-прежнему описывают только `name`; лишнее входное поле
`currentUserRole` игнорируется, как прочие неизвестные поля. При корректном
`name` и достаточных правах create сохраняет успех `201`, update — `200`:
это поле не вызывает `400`, не меняет membership и фактическую роль в ответе.
Дополнение раскрывает
только собственную роль: без списка участников, их идентификаторов/ролей,
`deletedAt` и других внутренних полей.

Обязательность фиксируется в общей Zod-схеме `projectSchema`; для значений
используется существующая единая shared-схема enum ролей, без дублирования
([ADR-012](../../../../docs/adr/012-api-contract.md)). После ревью спецификации
и тестов shared-контракт, API и типизированные web-фикстуры обновляются
согласованно; временно необязательное поле не является выполнением контракта.

## Поведение

- **create**: в одной транзакции создаётся `Project` + `ProjectMember(role=owner)`
  для текущего пользователя.
- **list**: проекты, где для пользователя есть `ProjectMember`; `deletedAt = null`.
- **update**: меняет `name`.
- **delete**: soft-delete — ставит `deletedAt`; проект (и его страницы) исчезают
  из выдачи. Восстановление/корзина — отдельная задача.

Доступ проверяет `ProjectAccessGuard` + `@RequireProjectRole` (ADR-011): достаёт
`projectId`, находит `ProjectMember` пользователя, сравнивает роль по иерархии
`owner > editor > viewer`.

Для дополнения о роли:

- **create** возвращает `currentUserRole = owner` по созданной membership.
- **list** возвращает роль пользователя отдельно для каждого проекта; **get**
  и успешный **update** — его фактическую роль, а не минимальную роль допуска
  (`viewer`/`editor`). Переименование само по себе роль не меняет.
- Роль доступна и у проекта без страниц. Она не выводится из Page, наличия
  данных, пробной мутации или ответа `403`.
- Это снимок серверных данных для интерфейса, а не разрешение будущих записей:
  backend проверяет актуальные права при каждой мутации независимо от ранее
  выданной роли и клиентского кэша. ACL и статусы ошибок ниже не ослабляются.
- На клиенте роль относится к server state (TanStack Query); отсутствующая или
  неизвестная роль никогда не разрешает запись. Мутационные контролы #136
  этим дополнением не реализуются.

## Крайние случаи

| Случай                                               | Ожидание                                                                |
| ---------------------------------------------------- | ----------------------------------------------------------------------- |
| create без авторизации                               | `401 UNAUTHORIZED`                                                      |
| create с пустым / слишком длинным `name`             | `400 VALIDATION_ERROR`                                                  |
| list — чужие проекты                                 | не видны                                                                |
| list — удалённые проекты                             | не видны                                                                |
| get: не участник                                     | `403 FORBIDDEN`                                                         |
| get / update / delete: несуществующий id             | `404 NOT_FOUND`                                                         |
| update ролью `viewer`                                | `403 FORBIDDEN`                                                         |
| delete ролью `editor` / `viewer`                     | `403 FORBIDDEN`                                                         |
| повторный delete уже удалённого                      | `404` — soft-deleted трактуется как несуществующий                      |
| get / patch уже удалённого                           | `404` — soft-deleted инертен во всех операциях                          |
| один проект читают owner, editor и viewer            | каждый получает собственный `currentUserRole` в list/get                |
| один пользователь с разными ролями в разных проектах | list/get возвращают соответствующую каждому проекту роль                |
| проект без страниц                                   | list/get содержат роль из membership без обращения к Page               |
| успешный update от owner / editor                    | ответ содержит соответственно `owner` / `editor`                        |
| посторонний либо удалённый проект                    | прежние фильтрация и `403`/`404`; Project и роли участников не выдаются |

## Взаимодействия

- **Prisma**: `Project`, `ProjectMember`, enum `ProjectRole` (ADR-011); `deletedAt`
  на `Project`. Миграция в git.
  Дополнение о роли использует существующий `ProjectMember.role`, новой
  миграции и нового хранения прав не требует.
- **Регистрация**: дефолтный проект создаётся с owner-membership; при последующем
  list/get его `currentUserRole` — `owner`. Ответ регистрации остаётся `{ user }`,
  Project или поле роли в него не добавляются.
- **Guard**: `ProjectAccessGuard` + `@RequireProjectRole`, код `FORBIDDEN` в общий
  error-shape.
- **Server state**: на фронте — TanStack Query (FE-3, [ADR-005](../../../../docs/adr/005-state-management.md)),
  вне этой задачи.

## Решения

- Повторный `delete` / любой доступ к уже удалённому проекту → `404`
  (soft-deleted трактуется как несуществующий во всех операциях).
- **Проверка существования (404) идёт раньше проверки прав (403).** Не участник,
  запрашивающий удалённый проект, получает `404`, а не `403` — не раскрываем факт
  существования.
- **Восстановление удалённого — вне scope этого модуля.** Корзина (restore) —
  отдельная фича с выделенным эндпоинтом (`POST /projects/:projectId/restore` или
  trash-namespace) и своим доступом; обычные `get` / `patch` над удалённым
  остаются `404`.

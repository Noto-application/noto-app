# Spec: Users — профиль, username и аватар

**Статус:** Draft
**Дата:** 2026-09-16
**Связанные:** [ADR-003](../../../../docs/adr/003-authentication.md), [ADR-012](../../../../docs/adr/012-api-contract.md), [ADR-017](../../../../docs/adr/017-image-storage.md), [auth.spec.md](../auth/auth.spec.md), issue #124

## Цель

Авторизованный пользователь читает свой профиль и задаёт отображаемое имя
(`username`): первый раз или смена, а также загружает, получает и удаляет
собственный аватар.

## Вне scope

- Создание пользователя — только в auth (`POST /auth/register`).
- Смена email и пароля, удаление аккаунта.
- Уникальный хэндл, публичные профили чужих пользователей, поиск по имени.
- Сброс `username` в `null` (только добавить или заменить).

## Контракт

ts-rest контракт в `@noto/shared` (`usersContract`). Единый shape ошибок
`{ code, message, details? }` ([ADR-012](../../../../docs/adr/012-api-contract.md)).
Все пути под префиксом `/api`. Запросы — `credentials: 'include'`.

| Метод  | Путь                                         | Кто                     | Тело                    | Успех            |
| ------ | -------------------------------------------- | ----------------------- | ----------------------- | ---------------- |
| GET    | `/users/me`                                  | текущий (access cookie) | —                       | `200 { user }`   |
| PATCH  | `/users/:userId`                             | только свой `userId`    | `{ username }`          | `200 { user }`   |
| POST   | `/users/me/avatar/uploads`                   | текущий (access cookie) | `{ contentType, size }` | `201 { upload }` |
| POST   | `/users/me/avatar/uploads/:uploadId/confirm` | владелец загрузки       | —                       | `200 { user }`   |
| DELETE | `/users/me/avatar`                           | текущий (access cookie) | —                       | `200 { user }`   |

Коды ошибок: `UNAUTHORIZED` 401, `FORBIDDEN` 403, `NOT_FOUND` 404,
`VALIDATION_ERROR` 400.

**Форма `user`** (тот же публичный DTO, что у auth register/login/me; без
`passwordHash`):

| Поле        | Тип              | Заметка                                               |
| ----------- | ---------------- | ----------------------------------------------------- |
| `id`        | `string` (uuid)  |                                                       |
| `email`     | `string`         |                                                       |
| `username`  | `string \| null` | `null`, пока пользователь не задал имя                |
| `createdAt` | `string` (ISO)   |                                                       |
| `avatar`    | `Avatar \| null` | Временное URL-представление; `null`, если аватара нет |

`Avatar` содержит `url` (короткоживущий presigned URL чтения), `contentType` и
`size`. URL создаётся для ответа API и никогда не сохраняется в PostgreSQL.
Клиент повторно получает актуальный URL через чтение профиля после истечения.

Ответ разрешения на загрузку (`upload`) содержит `uploadId`, `url`,
`method: "PUT"`, обязательные `headers` и время истечения `expiresAt`.
Bucket и storage key клиенту не назначаются.

Все ответы API, содержащие `user` (включая `/auth/me`), используют эту форму.
Если аватар назначен, ответ содержит актуальный временный URL для чтения;
отдельное получение аватара не открывает доступ к чужим профилям.

## Поведение

- **GET `/users/me`:** текущий пользователь из access cookie → `200 { user }`.
  `username` может быть `null`. Строки в БД нет, а токен ещё жив → `401`
  (как `GET /auth/me`), не `404`.
- **PATCH `/users/:userId`:** если `userId` не совпадает с id из токена →
  `403 FORBIDDEN` (без чтения БД, не раскрываем существование id). Свой id →
  trim пробелов по краям, длина 1–80 → сохранить → `200 { user }` с новым
  именем. Повторный PATCH заменяет имя.

Регистр и внутренние пробелы сохраняем (`Ivan Petrov` валиден). Уникальность
не проверяем: это отображаемое имя, не хэндл.

Register/login **не** принимают `username`; у нового пользователя поле `null`.

### Аватар

- Все операции с аватаром требуют access cookie. Пользователь работает только
  со своим аватаром и собственными загрузками.
- Разрешение на загрузку выдаётся только для JPEG, PNG или WebP размером больше
  нуля и не более 5 MiB (5 × 1024 × 1024 байта). API отклоняет неподдерживаемый
  `contentType` и превышение лимита до выдачи URL.
- При выдаче разрешения API генерирует непрозрачный случайный storage key,
  записывает загрузку со статусом `pending` в PostgreSQL и возвращает
  короткоживущий presigned `PUT` URL с требуемыми заголовками. Клиент загружает
  файл напрямую в приватный S3 bucket; credentials API клиенту не передаются.
- После загрузки клиент подтверждает `uploadId`. До смены аватара API проверяет,
  что pending-загрузка принадлежит текущему пользователю, объект существует,
  его фактический размер не превышает лимит, а формат подтверждается содержимым
  объекта (сигнатурой/декодированием), а не только расширением файла или
  переданным клиентом MIME type. Разрешены только JPEG, PNG и WebP; сохранённый
  `contentType` определяется по проверенному содержимому. Непрошедший проверку
  объект не становится аватаром.
- После проверки API нормализует изображение на сервере: применяет EXIF-
  ориентацию, уменьшает изображение так, чтобы обе стороны были не больше
  512 px (без увеличения), удаляет метаданные и кодирует результат в WebP.
  Результат не должен превышать 256 KiB. Превышение лимита результата означает
  ошибку подтверждения; текущий аватар остаётся без изменений.
- До записи нормализованного файла API сохраняет в PostgreSQL его новый
  непрозрачный случайный storage key и статус обработки. После успешной записи
  результата PostgreSQL-транзакция активирует нормализованный объект,
  обновляет ссылку пользователя, помечает исходную pending-загрузку для
  очистки и ставит прежний аватар в очередь отложенного удаления. Исходный
  загруженный объект никогда не назначается аватаром. Если обработка или
  запись результата не удалась, текущая ссылка на аватар не меняется;
  незавершённый объект результата остаётся учтённым в PostgreSQL для фоновой
  очистки.
- Только собственную успешно подтверждённую загрузку можно назначить аватаром.
  Подтверждение уже активированной загрузки идемпотентно. Ошибка загрузки или
  проверки не меняет текущий аватар.
- При подтверждённой замене PostgreSQL-транзакция назначает новый объект
  аватаром и ставит прежний объект в очередь удаления через 24 часа. При
  удалении аватара API убирает связь с профилем, но не удаляет профиль; файл
  также ставится в очередь отложенного удаления через 24 часа.
- API чтения своего профиля возвращает данные для отображения аватара и новый
  временный URL для чтения приватного объекта. В БД хранится storage key, не
  временный URL. Отсутствие аватара представляется как `avatar: null`.
- Незавершённые pending-загрузки истекают через 24 часа. Фоновая очистка
  удаляет их объекты из S3 и завершает/удаляет соответствующие записи. Она
  также очищает исходные объекты после успешной нормализации, незавершённые
  результаты обработки по сохранённым записям и объекты, поставленные на
  отложенное удаление. Состояние
  задач хранится в PostgreSQL, а не только в памяти; удаление идемпотентно,
  ошибки повторяются и не возвращают удалённую/заменённую ссылку в профиль.
- Общий storage transport не принимает произвольный bucket и не задаёт правила
  доступа сам. Изображения редактора в будущем используют этот транспорт, но
  получают отдельную авторизацию по ACL страницы/проекта; аватарные права на
  них не распространяются.

## Крайние случаи

| Случай                                                            | Ожидание                                                                            |
| ----------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| GET / PATCH без авторизации                                       | `401 UNAUTHORIZED`                                                                  |
| GET `/users/me`, пользователя уже нет в БД (cookie ещё жива)      | `401 UNAUTHORIZED` — как `/auth/me`                                                 |
| PATCH чужого `userId` (существующего или нет)                     | `403 FORBIDDEN`                                                                     |
| PATCH своего id, пользователя уже нет в БД                        | `404 NOT_FOUND`                                                                     |
| `username` пустой / одни пробелы / длиннее 80                     | `400 VALIDATION_ERROR`                                                              |
| `username` с пробелами по краям                                   | сохраняется обрезанным                                                              |
| пользователь без `username`                                       | GET `/users/me` и `/auth/me` — `username: null`, остальное работает                 |
| не-uuid в `:userId`                                               | `400 VALIDATION_ERROR`                                                              |
| POST разрешения без авторизации                                   | `401 UNAUTHORIZED`                                                                  |
| неподдерживаемый формат, нулевой размер или размер больше 5 MiB   | `400 VALIDATION_ERROR`, URL не выдаётся                                             |
| подтверждение чужого / неизвестного uploadId                      | отказ без назначения аватара; чужая загрузка не раскрывается                        |
| объект отсутствует, слишком велик или содержимое не JPEG/PNG/WebP | подтверждение отклонено, текущий аватар не меняется                                 |
| изображение не декодируется или обработка завершилась ошибкой     | подтверждение отклонено, текущий аватар не меняется                                 |
| нормализованный WebP больше 256 KiB                               | подтверждение отклонено, текущий аватар не меняется                                 |
| нормализация и запись результата успешны                          | активируется нормализованный объект, исходный объект очищается отдельно             |
| ошибка обработки/записи результата                                | текущий аватар не меняется, незавершённый результат очищается по сохранённой записи |
| повторное подтверждение уже назначенной загрузки                  | успешный идемпотентный ответ                                                        |
| подтверждение чужого, неизвестного или истёкшего uploadId         | отказ без назначения аватара и без раскрытия чужой загрузки                         |
| удаление аватара                                                  | связь становится `null`, профиль остаётся, файл удаляется фоновой задачей           |
| истекший URL чтения                                               | клиент запрашивает профиль повторно и получает новый URL                            |
| pending-загрузка старше 24 часов                                  | фоновая очистка удаляет объект и завершает запись                                   |
| ошибка удаления объекта из S3                                     | профиль не откатывается, задача остаётся для повторной попытки                      |

## Взаимодействия

- **Prisma:** на `User` опциональное поле `username String?` (без unique).
  Миграция в git. Создание пользователя по-прежнему в auth.
- **Auth:** публичный DTO общий; `toPublicUser` отдаёт `username`. Register не
  меняется. DTO профиля также содержит временное представление аватара; URL
  генерируется при ответе и не сохраняется в БД.
- **Storage / PostgreSQL:** бинарный файл хранится в приватном S3 bucket.
  PostgreSQL хранит объект, владельца, content type, размер, статус жизненного
  цикла, даты истечения/удаления, ключи объектов в процессе обработки и
  nullable-ссылку пользователя на текущий аватар. Активным становится только
  серверно нормализованный WebP-объект; исходная загрузка является временной.
  Временные URL не персистируются.
- **Очистка:** pending-записи и отложенные удаления устойчивы к перезапуску API;
  фоновый worker повторяет временно неуспешные удаления.
- **Server state:** на фронте — TanStack Query ([ADR-005](../../../../docs/adr/005-state-management.md));
  после PATCH инвалидировать и профиль, и `/auth/me`. Вне этой задачи.

## Решения

- Поле в API и БД — `username` (issue: «имя»). Не unique, не lowercase.
- Чужой профиль не читаем и не редактируем в этом модуле: GET только `/users/me`,
  PATCH чужого id → `403`. Публичный DTO содержит `email` — чужие профили
  отдельно, со своим DTO.
- Очистить имя нельзя: пустая строка после trim → `400`, не `null`.
- Файл загружается напрямую из браузера в S3 по presigned URL, назначается
  только после серверного подтверждения содержимого, а старый объект
  удаляется с задержкой 24 часа (ADR-017).
- При подтверждении API нормализует изображение до WebP не более 512×512 и
  256 KiB; обработка специфична для аватаров и не входит в общий storage
  transport.

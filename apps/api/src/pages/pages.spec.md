# Spec: Pages CRUD

**Статус:** Draft
**Дата:** 2026-08-17
**Связанные:** [ADR-011](../../../../docs/adr/011-authorization-acl.md), [ADR-012](../../../../docs/adr/012-api-contract.md), issues #45 (foundation), #46 (create/list), #47 (вложенность/move), #48 (контент), #49 (soft-delete)

## Цель

Бэкенд для страниц внутри проекта: создать / читать / переименовать /
редактировать контент / удалить, с вложенностью (дерево). Страница живёт
внутри проекта; проект — единица доступа ([ADR-011](../../../../docs/adr/011-authorization-acl.md)),
права наследуются от него.

## Вне scope

- Публикация страницы (`published`/`slug`, public URL) — отдельная задача.
- Восстановление из корзины (только пометка удаления) — отдельная задача.
- Совместное редактирование (Yjs) — контент хранится как снапшот, realtime позже.
- Валидация внутренней структуры блоков BlockNote — владение фронта (см. «Контент»).
- Drag-and-drop переупорядочивание в UI — фронт; бэк даёт `move`-API.

## Контракт

ts-rest контракт в `@noto/shared` ([ADR-012](../../../../docs/adr/012-api-contract.md)),
единый shape ошибок `{ code, message, details? }`. Тип `Page` реэкспортируется
фронтом (`entities/page`), поэтому имена полей — источник правды.

| Метод  | Путь                         | Кто       | Успех             |
| ------ | ---------------------------- | --------- | ----------------- |
| POST   | `/projects/:projectId/pages` | `editor`+ | `201 { page }`    |
| GET    | `/projects/:projectId/pages` | `viewer`+ | `200 { pages[] }` |
| GET    | `/pages/:id`                 | `viewer`+ | `200 { page }`    |
| PATCH  | `/pages/:id`                 | `editor`+ | `200 { page }`    |
| DELETE | `/pages/:id`                 | `editor`+ | `204`             |

Коды ошибок: `UNAUTHORIZED` 401, `FORBIDDEN` 403, `NOT_FOUND` 404,
`VALIDATION_ERROR` 400.

**Форма `Page`** (публичный DTO, без `deletedAt`):

| Поле        | Тип              | Заметка                                                |
| ----------- | ---------------- | ------------------------------------------------------ |
| `id`        | `string` (uuid)  |                                                        |
| `projectId` | `string` (uuid)  | Проект-владелец                                        |
| `parentId`  | `string \| null` | Родитель в дереве; `null` — корень проекта             |
| `title`     | `string`         | 1..200                                                 |
| `content`   | `Json`           | BlockNote-док (массив блоков), непрозрачный (см. ниже) |
| `position`  | `number` (int)   | Порядок среди сиблингов                                |
| `createdAt` | `string` (ISO)   |                                                        |
| `updatedAt` | `string` (ISO)   |                                                        |

**Роуты — форма (решение):** коллекция вложена в проект
(`/projects/:projectId/pages`), item — плоско (`/pages/:id`). Для item-роутов
`ProjectAccessGuard` резолвит `projectId` из страницы (`pageId` → `page.projectId`)
и дальше проверяет членство/роль как в Projects.

## Поведение

- **create**: создаёт страницу в проекте. Опционально `parentId` (в том же
  проекте) и `position`. Контент по умолчанию — пустой док. Владение — от проекта,
  отдельной записи доступа у страницы нет.
- **list**: страницы проекта, `deletedAt = null`, отсортированы по `position`
  (плоский список; дерево строит фронт по `parentId`).
- **get**: одна страница с `content`.
- **update (PATCH)**: частичный — любое подмножество `title` / `content` /
  `parentId` / `position` (autosave шлёт изменённое). Смена `parentId`/`position`
  = перемещение в дереве (см. «Вложенность»).
- **delete**: soft-delete — ставит `deletedAt`; страница и её поддерево исчезают
  из выдачи (каскадный soft-delete поддерева). Восстановление — отдельная задача.

Доступ — `ProjectAccessGuard` + `@RequireProjectRole` (ADR-011): для item-роутов
guard достаёт `projectId` из страницы, находит `ProjectMember`, сравнивает роль
по иерархии `owner > editor > viewer`.

### Контент

`content` — непрозрачный JSON (BlockNote-док). Бэк валидирует **только верхний
уровень**: это массив + суммарный размер **≤ 1 MB** на страницу. Внутреннюю
структуру блоков не валидируем — это владение BlockNote на фронте, дублировать
его схему хрупко. Лимит 1 MB — предохранитель от аномальных пейлоадов, при
необходимости пересмотрим по реальным докам.

### Вложенность и порядок

- `parentId` задаёт дерево; `null` — корень проекта.
- `position` (int) — порядок среди сиблингов одного `parentId`; при вставке между
  соседями позиции пересчитываются (простая целочисленная схема).
- **Перемещение** (`PATCH parentId`/`position`): новый `parentId` — в том же
  проекте; **защита от циклов** — страница не может стать потомком самой себя или
  своего поддерева.

## Крайние случаи

| Случай                                                  | Ожидание                          |
| ------------------------------------------------------- | --------------------------------- |
| create/list/get/... без авторизации                     | `401 UNAUTHORIZED`                |
| не участник проекта                                     | `403 FORBIDDEN`                   |
| несуществующий/удалённый `projectId` или `pageId`       | `404 NOT_FOUND`                   |
| не участник + удалённая/чужая страница                  | `404` (существование раньше прав) |
| пустой / слишком длинный `title` (>200)                 | `400 VALIDATION_ERROR`            |
| `content` не массив / превышен лимит размера            | `400 VALIDATION_ERROR`            |
| `parentId` на страницу другого проекта / несуществующую | `400` / `404`                     |
| move создаёт цикл (parent = сам/поддерево)              | `400 VALIDATION_ERROR`            |
| create/update/delete ролью `viewer`                     | `403 FORBIDDEN`                   |
| get/patch/delete уже удалённой страницы                 | `404` — soft-deleted инертен      |
| удалённый проект                                        | его страницы не видны             |
| delete страницы с детьми                                | каскадный soft-delete поддерева   |

## Взаимодействия

- **Prisma**: модель `Page` (`projectId` FK → Project cascade; `parentId`
  self-FK null; `content Json`; `position Int`; `deletedAt`). Индексы `projectId`,
  `parentId`. Миграция в git.
- **Guard**: `ProjectAccessGuard` (расширен резолвом `projectId` из `pageId`) +
  `@RequireProjectRole`.
- **Server state**: фронт — TanStack Query (`entities/page`, FE-3), вне этой задачи.

## Решения

- **Роль на все мутации страниц (create/update/move/delete) — `editor`+.**
  Страница — рабочий объект внутри проекта, не единица доступа; `owner`
  требуется только для операций над самим проектом (Projects delete). Viewer —
  только чтение.
- **Существование (404) раньше прав (403).** Как в Projects: не раскрываем факт
  существования удалённой/чужой страницы.
- **Каскадный soft-delete поддерева.** Удаление страницы помечает `deletedAt` у
  неё и всех потомков; выдача их скрывает. Реперентинг детей вверх не делаем.
- **Роуты:** коллекция вложена (`/projects/:projectId/pages`), item плоско
  (`/pages/:id`) с резолвом проекта из страницы в guard.
- **Контент — непрозрачный JSON**, валидируем shape (массив) + размер (≤ 1 MB),
  не блоки. Лимит пересматриваемый.

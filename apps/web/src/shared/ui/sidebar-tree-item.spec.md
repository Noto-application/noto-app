# Spec: SidebarTreeItem (строка дерева страниц)

**Статус:** Draft
**Автор:** daria-z
**Дата:** 2026-08-24
**Связанные:** issue #62, PR #70; потребитель — [PageTree](../../widgets/sidebar/page-tree.spec.md) (#54)

## Цель

Один ряд дерева страниц в сайдбаре: шеврон раскрытия, заголовок с иконкой и
место под действия строки. Только вёрстка — ни стора, ни запросов, ни логики
дерева, всё приходит пропсами.

## Контракт разметки

Строка — ряд из трёх зон: `[шеврон] [ссылка на страницу] [действия]`.

- **Шеврон — отдельная кнопка**, не часть ссылки: кнопка внутри `<a>` невалидна,
  и клик по шеврону не должен вести на страницу. На ней `aria-expanded`, в
  `aria-label` входит имя узла — «Развернуть «Обзор»».
- **Заголовок — ссылка с `href`**, а не кнопка: нужны Cmd- и средний клик,
  «копировать адрес», prefetch и объявление ссылкой у скринридера.
- **Активная страница — `aria-current="page"`** на ссылке; подсветка через
  `[aria-current='page']`, отдельного класса нет.
- **Слот действий присутствует всегда**, даже пустой: от него зависит ширина
  обрезки заголовка и тач-таргеты. Наполнение — не в этой задаче.
- **У листа на месте шеврона — распорка той же ширины**, иначе заголовки листьев
  съезжают относительно веток.
- **Отступ по глубине — внутри строки** (CSS-переменная от `depth`), не на
  вложенном списке: иначе подсветка при наведении идёт лесенкой.
- Роли `tree`/`treeitem` компонент не ставит, `tabindex` не хардкодит —
  структуру списка задаёт `PageTree` снаружи.

## Пропсы

```ts
/** Невалидные комбинации не выражаются типом. */
type BranchState = { hasChildren: false } | { hasChildren: true; isExpanded: boolean };

type SidebarTreeItemProps = BranchState & {
  title: string;
  href: string;
  depth: number;
  isActive: boolean;
  icon?: ReactNode;
  onToggle?: () => void;
};
```

- `title` — строка, а не `ReactNode`: из неё строятся `aria-label` шеврона,
  обрезка и подстановка «Без названия».
- `icon` — по умолчанию `FileText` из `lucide-react`.
- `onToggle` вызывается только у узлов с детьми.

## Состояния для stories

- **Структурные:** глубина 0–5; лист и ветка; раскрыт и свёрнут.
- **Интерактивные:** покой, hover, `:focus-visible` отдельно на ссылке и на
  шевроне, активная страница, активная + hover.
- **Контентные:** длинный заголовок с обрезкой; длинный заголовок на глубине 5;
  пустой заголовок → «Без названия»; заголовок из одного символа; с иконкой и
  без.
- **Среда:** тёмная тема; `pointer: coarse`; зум 200%; ширина контейнера
  240–320px.
- **Mini tree** — 4–5 строк в колонке.
- **Скролл-контейнер** — фиксированная высота, `overflow-y: auto`, два десятка
  строк: только здесь видно, обрезается ли кольцо фокуса у крайних строк.

Фокусные состояния снимаются клавиатурой — `:focus-visible` мышью не
воспроизводится, нужна play-функция с `userEvent.tab()`.

## Критерии приёмки

- [ ] Высота строки одинакова во всех состояниях, дерево не дёргается на hover.
- [ ] Кольцо фокуса не обрезается прокруткой сайдбара — проверять на первой и
      последней строке в истории со скролл-контейнером.
- [ ] Всё, что показывается по `:hover`, показывается и по `:focus-within`.
- [ ] Контраст: текст ≥ 4.5:1, иконки и кольцо фокуса ≥ 3:1, в обеих темах.
- [ ] При `pointer: coarse` тач-таргеты ≥ 44×44px, область нажатия расширяется
      псевдоэлементом, а не высотой строки.
- [ ] При зуме 200% и ширине 320px нет горизонтального скролла.
- [ ] `prefers-reduced-motion: reduce` — поворот шеврона не анимируется.
- [ ] Заголовок выделяется мышью: кликабельность не через абсолютный оверлей.
- [ ] Только `shared/ui`, без импортов из `widgets`, `features`, `entities`.
- [ ] Tailwind и `cn()`, как в остальном UI-kit; CSS-модулей в проекте нет.
- [ ] lint, typecheck и сборка Storybook зелёные.

## Вне scope

Меню строки «…» и кнопка «+» (только место под них) · drag-and-drop ·
клавиатурная навигация по дереву · запросы, стор, роутинг · виртуализация ·
ленивая подгрузка детей: список страниц приходит одним запросом.

# Spec: PageTree (сайдбар)

**Статус:** Draft
**Автор:** daria-z
**Дата:** 2026-08-23
**Связанные:** [ADR-002](../../../../../docs/adr/002-routing-and-domains.md), [ADR-005](../../../../../docs/adr/005-state-management.md), [ADR-008](../../../../../docs/adr/008-fsd-structure.md); issue #54 (первая половина — дерево; создание страницы — в `features/create-page`); зависит от #53 (`buildPageTree`, `usePagesList`) и #62 (`SidebarTreeItem`)

## Цель

Пользователь видит в сайдбаре дерево страниц текущего проекта и переходит
кликом на любую из них.

## Вне scope

- `buildPageTree` (#53) и `SidebarTreeItem` (#62) — потребляются, не реализуются здесь.
- Создание страницы — вторая половина issue #54,
  [features/create-page/create-page.spec.md](../../features/create-page/create-page.spec.md).
- Drag-and-drop, перемещение, удаление, ACL-скрытие кнопок по роли.
- Клавиатурная навигация по [ARIA APG для tree](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/)
  (стрелки, `Home`/`End`, roving `tabindex`) — отдельная задача. Здесь каждая
  строка фокусируется по `Tab` как обычная кнопка.

## Контракт

```tsx
// widgets/sidebar/ui/page-tree.tsx
export function PageTree({ projectId }: { projectId: string }): ReactNode;
```

**Предусловие.** Имена `usePagesList`, `buildPageTree` (`entities/page/lib/`) и
ключи `pages.list(projectId)` — целевые после #53; в `main` сейчас `usePages` и
`pageKeys.byProject`. PageTree мержится только после #53.

- `projectId` родитель берёт из `usePage(pageId).projectId` — не из URL и не из
  Zustand (ADR-002).
- Асимметрия «`projectId` пропсом, `pageId` из хука» намеренная: источник
  проекта у родителя может меняться (активная страница, переключатель
  проектов), а активная страница по определению одна и живёт в маршруте
  (ADR-002).
- Активную страницу компонент читает сам: `useParams<{ pageId?: string }>()` —
  на `/app` параметра нет, поэтому поле опционально.
- Данные — `usePagesList(projectId)` из `entities/page`, дерево —
  `buildPageTree(pages)`, узлы — `SidebarTreeItem` из `shared/ui`.
- Порядок узлов и сортировку по `position` задаёт `buildPageTree` (#53); виджет
  рендерит массив как есть и не сортирует.
- Раскрытие узлов — `useSidebarStore.collapsedPageIds: Set<string>` +
  `togglePage(pageId)` (расширение существующего стора). Поле хранит
  **свёрнутые** узлы, в отличие от `expandedProjectIds`: дерево по умолчанию
  раскрыто целиком, поэтому дешевле хранить исключения.
- Свёрнутые узлы живут только в памяти вкладки: после перезагрузки страницы
  дерево снова раскрыто целиком, в `localStorage` ничего не сохраняем. При
  смене проекта `collapsedPageIds` не очищается — id чужих страниц безвредны,
  ни с одним узлом не совпадут.
- Строка — контейнер `role="treeitem"` с двумя самостоятельными контролами:
  кнопка-chevron (`aria-expanded`, `aria-label` «Развернуть»/«Свернуть») и
  `Link` навигации на оставшуюся ширину. Одной кнопкой или одной ссылкой строка
  быть не может: вложенные интерактивные элементы невалидны в HTML.
- Роли: элемент навигации строки — `Link` из `next/link`, **без** ARIA-ролей;
  `aria-expanded` приходит пропсом. Роли `tree` (контейнер), `treeitem`,
  `aria-level` (1 на корне, +1 на уровень) и `aria-selected` (обязателен для
  `treeitem`, равен `isActive`) ставит виджет. Требует правки критериев #62, где
  строка сейчас `<button type="button">` и роль на ней допускается.
- Разметка плоская: все `treeitem` — прямые потомки контейнера `role="tree"`,
  уровень передаётся через `aria-level`; `role="group"` не используется.

## Поведение

1. `isLoading` → `Skeleton`.
2. Загружено → рекурсивный рендер дерева; `depth` растёт на уровень,
   `hasChildren=false` → без chevron.
3. Дерево по умолчанию раскрыто целиком; `collapsedPageIds` хранит свёрнутые.
4. Строка — `Link` из `next/link` с ``href={`/app/${id}`}``, независимо от
   наличия детей: работают Cmd- и средний клик («открыть в новой вкладке»), а
   скринридер объявляет ссылку, а не кнопку. `router.push` не используем.
5. Клик по chevron (только у узлов с детьми) → `togglePage(id)`: chevron —
   соседний контрол, а не часть ссылки, поэтому навигации не происходит.
6. `pageId` из URL совпал с id узла → `isActive`.

Разделение «строка ведёт на страницу, chevron сворачивает» требует правки #62:
сейчас `SidebarTreeItem` — один `<button>` с одним `onClick`, а нужны два
контрола в строке (`href` у ссылки, `onToggle` у chevron). Единый обработчик
означал бы, что страницы с вложенными из сайдбара не открываются вовсе
([обсуждение в PR #70](https://github.com/Noto-application/noto-app/pull/70#discussion_r3838266613)).

## Крайние случаи

| Случай                                                       | Ожидание                                                                                                                                                              |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `usePagesList` в загрузке                                    | `Skeleton`, не пустой список и не дерево                                                                                                                              |
| `isError` или `data === undefined` при `isLoading === false` | Дерево не строится, `InlineAlert` `variant="danger"` «Не удалось загрузить страницы»; тост и 401-редирект — на общем error-handler (FE-4)                             |
| Нет активной страницы (`/app` без `pageId`)                  | Родитель не рендерит `PageTree`: `projectId` неизвестен, сайдбар показывает только статичные пункты                                                                   |
| `usePage(pageId)` ещё грузится                               | То же: `PageTree` не смонтирован, пока нет `projectId`                                                                                                                |
| Проект без страниц                                           | `EmptyState` как в story `Default`: «Нет страниц» + «Создайте первую страницу в этом проекте», в слоте `action` — кнопка «Создать страницу» из `features/create-page` |
| Все страницы на одном уровне                                 | Плоский список, `depth=0`, без chevron                                                                                                                                |
| 2+ уровня вложенности                                        | `depth` растёт на каждом уровне, chevron — только у узлов с детьми                                                                                                    |
| Активная страница — вложенный узел                           | `isActive` только у неё, не у родителей                                                                                                                               |
| Клик по chevron свёрнутого родителя с активным потомком      | Поддерево раскрывается, `isActive` и URL не меняются                                                                                                                  |
| Скринридер                                                   | `role="tree"` + `role="treeitem"` с `aria-level` и `aria-selected`                                                                                                    |

## Взаимодействия

Состояние по матрице [ADR-005](../../../../../docs/adr/005-state-management.md):
`pageId`/`projectId` — URL, список страниц — TanStack Query, свёрнутые узлы —
Zustand (`useSidebarStore`).

`togglePage` — логика стора, значит покрывается тестом первым в
`use-sidebar-store.test.ts`, а не только через рендер виджета.

Кнопка «Создать страницу» в пустом состоянии приходит из `features/create-page` —
импорт `widgets → features` разрешён порядком слоёв
[ADR-008](../../../../../docs/adr/008-fsd-structure.md).

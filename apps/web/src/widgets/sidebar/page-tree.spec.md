# Spec: PageTree (сайдбар)

**Статус:** Draft
**Автор:** daria-z
**Дата:** 2026-08-23
**Связанные:** [ADR-002](../../../../../docs/adr/002-routing-and-domains.md), [ADR-005](../../../../../docs/adr/005-state-management.md), [ADR-008](../../../../../docs/adr/008-fsd-structure.md); issue #54 (первая половина — дерево; создание страницы — в `features/create-page`); issue #84 (кнопка «+» вложенного создания, контракт — [create-page.spec.md](../../features/create-page/create-page.spec.md)); зависит от #53 (`buildPageTree`, `usePagesList`) и #62 (`SidebarTreeItem`, спека — [sidebar-tree-item.spec.md](../../shared/ui/sidebar-tree-item.spec.md))

## Цель

Пользователь видит в сайдбаре дерево страниц текущего проекта и переходит
кликом на любую из них.

## Вне scope

- `buildPageTree` (#53) и `SidebarTreeItem` (#62) — потребляются, правки в них
  делаются в своих задачах. Пока `SidebarTreeItem` не готов, строку рисует
  временный `ui/page-tree-row.tsx` по контракту
  [sidebar-tree-item.spec.md](../../shared/ui/sidebar-tree-item.spec.md):
  подмена сведётся к замене импорта.
- Логика создания и её контракт — [features/create-page/create-page.spec.md](../../features/create-page/create-page.spec.md);
  дерево только кладёт кнопку «+» в слот действий и передаёт ей `projectId`
  дерева и `parentId` строки.
- Меню «…» остаётся в слоте рядом с «+»: пункты «Переместить» / «Удалить» и их
  сценарии не меняются.
- Вынос кнопки «+» в `SidebarTreeItem` (#62) — не в этой задаче; слот действий
  наполняет виджет, контракт `SidebarTreeItem` не трогаем.
- Изменение сценариев перемещения, удаления и drag-and-drop, ACL-скрытие
  кнопок по роли (роль на проекте API не отдаёт — кнопки видны всем).

## Контракт

```tsx
// widgets/sidebar/ui/page-tree.tsx
export function PageTree({ projectId }: { projectId: string }): ReactNode;
```

**Предусловие.** Имена `usePagesList`, `buildPageTree` (`entities/page/lib/`) и
ключи `pages.list(projectId)` — целевые после #53; в `main` сейчас `usePages` и
`pageKeys.byProject`. Мержится после #53.

- `projectId` — пропс, родитель берёт его из `usePage(pageId).projectId`
  (ADR-002).
- Активную страницу компонент читает сам: `useParams<{ pageId?: string }>()` —
  на `/app` параметра нет.
- Данные — `usePagesList(projectId)`, дерево — `buildPageTree(pages)`, узлы —
  `SidebarTreeItem` из `shared/ui`.
- Готовый `usePageTree` (#53) не берём, хотя он делает то же одним хуком:
  раскрытие предков активной страницы идёт по `parentId` **плоского** списка,
  а `usePageTree` отдаёт только дерево — предков в нём пришлось бы искать
  рекурсивным обходом.
- Плоский список приходит отсортированным: бэкенд отдаёт `list` по `position`
  (вторичный ключ `createdAt`, см. `apps/api/src/pages/pages.spec.md`).
  `buildPageTree` (#53) сохраняет этот порядок; ни он, ни виджет не сортируют.
- Раскрытие — `useSidebarStore.collapsedPageIds: Set<string>` +
  `togglePage(pageId)` и `expandPages(pageIds)` (расширение стора). Хранятся
  **свёрнутые** узлы: по умолчанию дерево раскрыто целиком.
- `collapsedPageIds` живёт в памяти вкладки, в `localStorage` не сохраняется;
  при смене проекта не очищается.
- Раскрытие предков активной страницы **очищает** `collapsedPageIds` через
  `expandPages`, а не подменяет состояние при рендере: иначе шеврон показывал бы
  «раскрыто», а клик по нему не сворачивал бы узел. Отдельное действие нужно
  потому, что `togglePage` не идемпотентен — на уже раскрытом предке он сработал
  бы наоборот.

**Разметка и доступность.** Навигация с раскрытием, не ARIA-дерево:
`<nav aria-label="Страницы">` со вложенными списками, дети узла — вложенный
`<ul>` внутри его `<li>`. Роли `tree`/`treeitem` и `aria-level` не
используются.

- Строка — три зоны: кнопка-шеврон, ссылка на страницу, слот действий. Слот
  присутствует всегда, даже пустой: от него зависит ширина обрезки заголовка.
- В слоте действий рядом с меню «…» — кнопка «+» (#84) с доступным именем
  «Создать страницу внутри «{title}»», где `{title}` — заголовок строки.
  «+» не заменяет и не прячет «…».
- «+» показывается по `:hover` и `:focus-within` строки, при `pointer: coarse`
  видна всегда. Ширина слота фиксирована, чтобы обрезка заголовка не зависела
  от видимости «+».
- Шеврон и ссылка — отдельные контролы; вкладывать один в другой нельзя.
- `aria-expanded` — на шевроне, его `aria-label` включает имя узла («Развернуть
  «Обзор»»).
- Активная страница — `aria-current="page"` на ссылке, подсветка через
  `[aria-current='page']`.
- Клавиатура — обычный `Tab`; роуминг `tabindex` и стрелки не нужны.
- Отступ по глубине — внутри строки, не на вложенном `<ul>`: иначе подсветка
  при наведении идёт лесенкой.

## Поведение

1. `isLoading` → `Skeleton`.
2. Загружено → рекурсивный рендер; `depth` растёт на уровень, у листа вместо
   шеврона распорка той же ширины.
3. По умолчанию дерево раскрыто целиком; `collapsedPageIds` хранит свёрнутые.
4. Строка — ссылка с ``href={`/app/${id}`}``, независимо от наличия детей;
   `router.push` не используем.
5. Клик по шеврону (только у узлов с детьми) → `togglePage(id)`, навигации нет.
6. `pageId` из URL совпал с id узла → `aria-current="page"` на его ссылке.
7. Переход на страницу убирает её предков из `collapsedPageIds`: активная
   страница всегда видна в дереве, в том числе при заходе по прямой ссылке.
8. В слоте действий каждой строки есть кнопка «…» с доступным именем
   «Действия для «Название»». Она открывает меню «Переместить» / «Удалить»;
   отдельной кнопки удаления в строке нет.
9. Выбор пункта закрывает меню и открывает соответствующий диалог. Закрытие
   меню не размонтирует открытый диалог. Отмена возвращает фокус на «…».
10. «Удалить» открывает подтверждение для выбранной страницы и её потомков.
    Запрос отправляется только после подтверждения; отмена не отправляет
    запрос. Во время удаления подтверждение и отмена заблокированы. Ошибка
    оставляет диалог открытым для повтора; уведомления и переход после успеха
    сохраняют поведение `features/delete-page`.
11. Меню и действия доступны мышью и клавиатурой. Открытие меню, выбор пункта
    и отмена диалога не меняют активную страницу или раскрытие веток и не
    запускают перетаскивание.
12. Кнопка «+» в строке создаёт вложенную страницу: `parentId` — id строки,
    проект — `projectId` дерева, без фолбэка на другой проект
    ([create-page.spec.md](../../features/create-page/create-page.spec.md)).
13. Пока вложенная мутация в полёте, все «+» дерева заблокированы — повторный
    клик второго запроса не шлёт. Меню «…» остаются рабочими.
14. Успех: список страниц инвалидируется, родитель раскрыт идемпотентно (уже
    раскрытый не меняется), затем переход на новую страницу.
15. Ошибка: строка не раскрывается и перехода нет; тост — по
    features/create-page, после завершения «+» снова доступны.

## Крайние случаи

| Случай                                                       | Ожидание                                                                                                                                                         |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `usePagesList` в загрузке                                    | `Skeleton`, не пустой список и не дерево                                                                                                                         |
| `isError` или `data === undefined` при `isLoading === false` | Дерево не строится, `InlineAlert` `variant="danger"` «Не удалось загрузить страницы»; тост и 401-редирект — на общем error-handler (FE-4)                        |
| Нет активной страницы (`/app` без `pageId`)                  | Родитель не рендерит `PageTree`: `projectId` неизвестен                                                                                                          |
| `usePage(pageId)` ещё грузится                               | То же: не смонтирован, пока нет `projectId`                                                                                                                      |
| Проект без страниц                                           | `EmptyState` как в story `Default`: «Нет страниц» + «Создайте первую страницу в этом проекте»; кнопка в слоте `action` — вместе с созданием страницы (подзадача) |
| Все страницы на одном уровне                                 | Плоский список, `depth=0`, без шевронов                                                                                                                          |
| 2+ уровня вложенности                                        | `depth` растёт на каждом уровне, шеврон — только у узлов с детьми                                                                                                |
| Активная страница — вложенный узел                           | `aria-current="page"` только у неё, не у родителей                                                                                                               |
| Клик по шеврону свёрнутого родителя с активным потомком      | Поддерево раскрывается, активная страница и URL не меняются                                                                                                      |
| Прямая ссылка на страницу внутри свёрнутого родителя         | Предки раскрываются, активная страница видна                                                                                                                     |
| Клик по «+» у листа                                          | Создаётся первый потомок; после успеха строка становится веткой и раскрыта                                                                                       |
| Клик по «+» у свёрнутого родителя                            | После успеха родитель раскрыт, новый потомок виден                                                                                                               |
| Двойной клик по «+» одной строки                             | Один запрос; пока он в полёте, все «+» дерева заблокированы                                                                                                      |
| Клик по «+» в двух разных строках                            | Второй запрос не отправляется: одна вложенная мутация за раз, все «+» дерева заблокированы                                                                       |
| Ошибка создания из строки                                    | Тост, строка не раскрывается, перехода нет; после завершения «+» снова доступны                                                                                  |

## Взаимодействия

Состояние по матрице [ADR-005](../../../../../docs/adr/005-state-management.md):
`pageId`/`projectId` — URL, список страниц — TanStack Query, свёрнутые узлы —
Zustand (`useSidebarStore`).

`togglePage` и `expandPages` покрываются отдельными тестами (тест-первым) в
`use-sidebar-store.test.ts`.

Кнопка «Создать страницу» в пустом состоянии приходит из `features/create-page`
и появится вместе с подзадачей создания — сейчас слот `action` пуст.

Общее меню действий объединяет публичные API `features/move-page` и
`features/delete-page` на уровне `widgets/sidebar`. Сценарии и диалоги
остаются в своих features; импорты между ними не добавляются.

Кнопку «+» отдаёт `features/create-page`, рендерит виджет — как кнопку
пустого состояния. Дерево передаёт ей `projectId` и `parentId`; активный
проект, фолбэк и `403` — в create-page.spec.md.

Логика «+» проверяется тестами виджета (переданные `parentId`/`projectId`,
одна вложенная мутация за раз, раскрытие родителя и переход); их пишут по
этой спеке и ревьюят до кода. Видимость по hover/focus, `pointer: coarse` и
фиксированная ширина слота — вёрстка: проверяются вручную, unit-тестами не
дублируются.

В сайдбаре получаются два навигационных лендмарка, поэтому метка нужна обоим:
дерево — `aria-label="Страницы"`, существующий `<nav>` статичных пунктов в
`sidebar.tsx` — `aria-label="Разделы"`. Без меток скринридер объявит
«навигация» дважды.

## Отвергнутые альтернативы

- **ARIA-дерево** (`role="tree"`, `aria-level`, роуминг `tabindex`, стрелки
  `→`/`←`) — требует клавиатурной модели, которую мы сейчас не пишем; роли без
  неё обещают скринридеру навигацию, которой нет.
- **Одна кнопка-строка с зонами клика** (виджет решает по `event.target`) —
  сворачивание доступно только мышью, и кнопка не даёт Cmd- и средний клик.

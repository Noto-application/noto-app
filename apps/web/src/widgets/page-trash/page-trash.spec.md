# Spec: Корзина страниц — frontend (#128)

**Статус:** Draft
**Дата:** 2026-11-02
**Связанные:** issue #128, #156; [BE-корзина](../../../../api/src/pages/trash.spec.md), [ADR-005](../../../../../docs/adr/005-state-management.md), [ADR-012](../../../../../docs/adr/012-api-contract.md), [ADR-013](../../../../../docs/adr/013-spec-driven-development.md)

## Цель

Показать удалённые страницы выбранного проекта и позволить восстановить одну
страницу с обновлением корзины и дерева без перезагрузки приложения.

## Вне scope

Окончательное удаление, очистка корзины, массовые операции, восстановление
проектов, автоматическое восстановление предков/детей, изменение правил BE.

## Контракт

Источник истины — `packages/shared/src/api/contract/pages.ts` и схемы
`packages/shared/src/api/schemas/page.ts`. Используется существующий
`apiClient` с HttpOnly cookie, `credentials: 'include'` и общим refresh на 401.

| Запрос                                                       | Ответ                                                | Права   |
| ------------------------------------------------------------ | ---------------------------------------------------- | ------- |
| `GET /api/projects/:projectId/trash/pages?limit=50&cursor=…` | `{ pages: TrashPage[], nextCursor: string \| null }` | viewer+ |
| `POST /api/pages/:pageId/restore` без тела                   | `{ page: Page }`                                     | editor+ |

`TrashPage` содержит `id`, `projectId`, `parentId`, `title`, `position`,
`deletedAt` (ISO); контента в списке нет. Типы выводятся из общего контракта,
локальная копия DTO запрещена. Список плоский, порядок BE:
`deletedAt DESC, id ASC`. Курсор непрозрачный, клиент только передаёт его назад.

### Навигация

Маршрут: `/app/trash?projectId=<uuid>`. Открытие, перезагрузка и история браузера
сохраняют выбранный проект. Смена проекта меняет URL; Zustand для ID не нужен.

Из `/app/[pageId]` ссылка сайдбара берёт проект из метаданных страницы и
записывает его в URL корзины. На остальных экранах открывается `/app/trash`:
пользователь выбирает доступный проект через существующий список проектов;
выбор записывается в URL. Отсутствующий или невалидный ID не запускает trash
запрос. Первый проект автоматически не подставляется. Пустой список проектов
имеет отдельное состояние. Состояния загрузки/ошибки списка проектов и повтор
также видимы. Прямой URL проекта не требует наличия живой страницы.

### Состояния

- Загрузка; плоский список с названием, локализованной датой удаления и
  действием «Восстановить»; пустая корзина.
- Ошибка чтения с повтором, отдельно отсутствие доступа (`403`) и недоступный
  проект (`404`). Ошибки не превращаются в пустую корзину.
- «Показать ещё» при `nextCursor !== null`; ошибка следующей порции сохраняет
  уже загруженные строки и позволяет повторить её загрузку.
- Восстановление блокирует повторное действие для той же страницы, включая
  два вызова до следующего React-render и повторное открытие корзины после
  размонтирования строки, пока исходный запрос выполняется. Другие строки
  остаются доступны.
- При успехе список корзины и дерево запрашиваются заново; уведомление
  «Страница восстановлена» содержит ссылку `/app/<returned page.id>`.
  Автоматического перехода к редактору нет.
- При ошибке строка сохраняется, отображается причина, доступен ручной повтор.

## Поведение и крайние случаи

1. Восстанавливается только выбранная страница, дети остаются в корзине.
   BE сохраняет родителя и контент, добавляет страницу в конец живых siblings.
   FE не рассчитывает новую позицию и не строит восстановленное поддерево.
2. `409` с валидным `details.blockedBy` объясняет, какого предка нужно сначала
   восстановить. Предок может отсутствовать среди загруженных строк. В #128
   показываем имя и инструкцию, без автоматического POST или скрытого обхода
   корзины. Пользователь восстанавливает предка отдельным явным действием.
3. `409` без details сообщает о невозможности восстановления в текущем дереве.
   Неизвестные details не ломают экран; использовать общую ошибку конфликта.
4. Restore `403`: недостаточно прав, строка остаётся. DTO проекта и корзины
   сейчас не содержат роли; отсутствие живых страниц не позволяет узнать роль
   через Page. Поэтому FE не обещает предварительно скрыть действие у viewer;
   BE остаётся источником проверки, отказ отображается явно.
5. Restore `404`: страница уже восстановлена/недоступна либо проект удалён.
   Это не успех; нет success-уведомления. Обновить корзину и дерево, чтобы
   убрать устаревшую строку или показать недоступность проекта.
6. Ошибка сети/5xx: без автоматического повтора POST, строка остаётся;
   повтор — только явное действие. GET можно повторить кнопкой.
7. Смена проекта разделяет query cache. Завершившийся restore старого проекта
   обновляет именно его ключи, не меняет текущий URL и данные другого проекта.
8. Если POST успешен, но повторный GET упал, успех операции не превращается в
   «не восстановлено»: показать ошибку обновления данных и повтор GET.
9. При удалении страницы существующим UI инвалидировать корзину её проекта,
   иначе возврат на уже открывавшуюся корзину может показывать старые данные.

## Взаимодействия

URL определяет выбранный проект и открытую страницу. TanStack Query хранит
server state корзины и метаданные страниц; данные разных проектов изолированы.
Zustand хранит только UI-состояние. Контент восстановленной страницы не должен
становиться отдельной копией состояния редактора.

Восстановление обновляет корзину, дерево проекта и метаданные восстановленной
страницы, включая ранее полученный ответ об её отсутствии. Удаление страницы
обновляет корзину соответствующего проекта.

## Сценарии тестирования

- Запрос списка передаёт проект, лимит и непрозрачный серверный курсор;
  восстановление отправляется без тела. Ошибки API сохраняют код и details.
- Пагинация сохраняет загруженные строки, останавливается на `nextCursor = null`
  и позволяет повторить загрузку следующей порции после ошибки.
- Смена проекта изолирует данные. Отсутствующий или невалидный ID не вызывает
  запрос корзины; выбор проекта и история навигации определяются URL.
- Восстановление блокирует повторный запрос, в том числе до следующего render
  и после переключения проекта с возвратом до завершения операции.
- Успешное восстановление обновляет активные корзину и дерево, сбрасывает
  устаревшие метаданные и показывает уведомление со ссылкой на страницу.
- Ошибка восстановления сохраняет строку и позволяет ручной повтор;
  автоматического повтора POST нет. Для `403`, `404` и `409` проверяются
  соответствующие сообщения и отсутствие ложного успеха.
- Ошибка исходного восстановления видна после повторного открытия корзины,
  включая конфликт с предком вне загруженной порции. Новая попытка сбрасывает
  предыдущую ошибку; ошибки других проектов и страниц не отображаются.
- Ошибка обновления списка после успешного POST отображается отдельно и
  позволяет повторить GET, не выдавая восстановление за неуспешное.
- Удаление инвалидирует корзину проекта, даже если метаданные страницы
  загружались только в дереве или отсутствуют в кеше.

# Spec: Календарь страниц — frontend

**Статус:** In progress
**Дата:** 2026-09-21
**Связанные:** [ADR-002](../../../../../docs/adr/002-routing-and-domains.md), [ADR-004](../../../../../docs/adr/004-data-fetching.md), [ADR-005](../../../../../docs/adr/005-state-management.md), [ADR-008](../../../../../docs/adr/008-fsd-structure.md), [ADR-011](../../../../../docs/adr/011-authorization-acl.md), [ADR-014](../../../../../docs/adr/014-responsive-strategy.md), [ADR-015](../../../../../docs/adr/015-rich-text-editor.md), issue #132 (эта спека), #133–#139 (декомпозиция); API-источник правды — [calendar.spec.md](../../../../../apps/api/src/calendar/calendar.spec.md); библиотека-кандидат — [RFC-005](../../../../../docs/rfc/005-supplementary-libraries.md) (Draft, не утверждён)

## Цель

Пользователь видит страницы проекта в месячной сетке, открывает их, создаёт
страницу на день, переносит и снимает дату, а также встраивает календарь
блоком в редактор. Модель, API, ACL и жизненный цикл — в
[API-спеке](../../../../../apps/api/src/calendar/calendar.spec.md); здесь —
URL, состояние, представление и блок.

## Вне scope

- Независимые календари отдельных страниц, Notion databases, произвольные
  свойства.
- Timed-события, week/day view, recurrence, ICS, внешний sync, Telegram.
- Realtime-синхронизация и обязательный DnD (DnD — #138, опция, не блокер
  релиза).
- Финальный выбор библиотеки (FullCalendar Standard — кандидат, решение за
  #133) и точное место адаптера/интеграции BlockNote.
- Восстановление из корзины и проекта — внешняя зависимость #128 (см.
  [API-спеку](../../../../../apps/api/src/calendar/calendar.spec.md), «Жизненный
  цикл»).
- Month plan и RFC-005 не являются принятыми решениями.

## Контракт

### URL и навигация

Экран: `/app/calendar?projectId=<uuid>&month=YYYY-MM`. Проект и месяц — только
в URL ([ADR-002](../../../../../docs/adr/002-routing-and-domains.md),
[ADR-005](../../../../../docs/adr/005-state-management.md)).

- Переход из сайдбара с открытой страницы несёт её `projectId`.
- Нет `projectId` в прямой ссылке: после загрузки доступных проектов —
  канонический `router.replace` на первый доступный проект в серверном
  порядке, видимо выбранный; нет проектов → empty state «нет проекта».
- Нет `month`: текущий локальный календарный месяц и канонический `replace`.
- Невалидный синтаксис `projectId` или `month`: состояние «невалидная ссылка»,
  запрос не отправляется, есть действие к каноническому доступному
  проекту/текущему месяцу.
- Синтаксически валидный, но недоступный: `403` → forbidden, `404` → проект
  недоступен; молчаливого fallback нет.
- Прямая валидная ссылка работает.
- Будущий переключатель проекта использует URL и в v1 может оставаться
  выключенным; смена проекта сохраняет валидный месяц, закрывает/сбрасывает
  формы и делает `push` URL.
- prev/next/today делают `push` URL; back/forward рендерят состояние
  исключительно из URL.
- Формы захватывают контекст проекта; при смене контекста отменяются/сбрасываются;
  submit отказывает при устаревшем контексте.

### Состояние (матрица [ADR-005](../../../../../docs/adr/005-state-management.md))

| Слой            | Что хранит                                     |
| --------------- | ---------------------------------------------- |
| URL             | `projectId`, `month` экрана                    |
| TanStack Query  | записи календаря, заголовки, роль пользователя |
| RHF / локальный | черновики форм                                 |
| Локальный React | месяц каждого блока (независимо)               |
| Zustand         | только UI                                      |
| Yjs + BlockNote | только документ редактора                      |

### Query keys и инвалидация

Ключи с префиксом по проекту и точным `[from, to)`:

```ts
calendarEntryKeys.project(projectId); // ['calendar-entry', projectId]
calendarEntryKeys.range(projectId, from, to); // [...calendarEntryKeys.project(projectId), 'range', from, to]
```

- `from`/`to` — не календарные 28–31 день месяца, а фактически видимая
  месячная сетка: от первого дня недели первой строки до последнего дня
  недели последней строки включительно. Сетка занимает до 6 недель и
  **включает дни соседних месяцев**; карточки этих соседних дней приходят из
  того же ответа `[from, to)`, без отдельного запроса. Формулировка «записи за
  месяц» ниже означает именно видимую сетку, а не только календарный месяц.
- Мутации инвалидируют все календарные диапазоны проекта.
- create дополнительно инвалидирует список/дерево страниц и detail новой Page.
- assign/change/remove обновляют диапазоны записей и релевантный detail/list
  затронутой Page.
- Переименование Page инвалидирует префикс проекта, чтобы обновился заголовок.

Спека фиксирует наблюдаемый результат, а не механику (optimistic/refetch).

### Обновление на клиенте

Для календарных диапазонов переопределяем текущие дефолты: refetch при
возврате фокуса окна и переподключении, плюс polling раз в 60 секунд, только
пока компонент смонтирован и документ видим. Данные «eventual» — realtime не
обещаем. Интервал 60 секунд принят (бывший открытый вопрос №2).

### Роль пользователя

`projectSchema` сейчас не содержит прав. Принято добавить `currentUserRole`
(`owner | editor | viewer`) в ответы Project, серверно-вычисляемый для
запрашивающего, — как отдельную prerequisite-задачу до UI, **вне #134** (бывший
открытый вопрос №1). UI выводит мутационные аффордансы из неё; дубля
capabilities нет; никогда не определяем права пробным запросом/`403`.

### Действие в TopbarMenu текущей Page

На экране Page (`/app/[pageId]`) `TopbarMenu` текущей Page даёт действие
«Назначить дату», когда у Page нет даты; когда дата есть — смену и снятие
даты. Действие доступно и для вложенной Page: назначение/смена/снятие
сохраняет её `parentId` и структуру дерева. Это та же мутация
assign/change/remove, что и из формы карточки календаря: нового
контракта/состояния не вводит, правила кэша и инвалидации — из разделов
выше. Аффорданс виден только `owner`/`editor`; `viewer` его не видит.
Реализация действия — в #136. Существующая заглушка `TopbarMenu` до
#136 не меняется; точное представление формы (поповер/диалог) — деталь #136 и
здесь не фиксируется.

### Блок календаря в редакторе

- Обязательный v1: пункт slash menu.
- Проект берётся из содержащей Page, никогда не сохраняется пропом.
- Персистим только тип блока и минимальные структурные/версионные пропсы,
  если их требует BlockNote: **без** `projectId`, записей, заголовков,
  query-кэша, месяца.
- Данные и формы те же; viewer — read-only; карточки ведут на `/app/[pageId]`.
- Месяц локален для каждого инстанса; навигация не порождает транзакцию
  документа/undo/Yjs. Несколько блоков делят записи/кэш Query, но месяц
  независим. Удаление блока удаляет только блок.
- REST `editor.document` и collab `Y.XmlFragment` должны roundtrip-ить один
  тип через одно определение схемы; #131 — OPEN и не prerequisite для
  написания спеки, но #133 обязан проверить на durable-пути `editorMode` и
  текущем PR до production. Финальное место адаптера/интеграции здесь не
  утверждается.
- Фокус/клик/формы/узкая колонка: интерактивные контролы не превращаются
  случайно в правку текста или перетаскивание блока; клавиатура и touch
  работают; оверлей формы не пишет в документ редактора; безопасный
  overflow/адаптив ([ADR-014](../../../../../docs/adr/014-responsive-strategy.md)).
- Clipboard: внутреннее копирование блока между Page сохраняет только тип, без
  записей; вставленный блок резолвит проект целевой Page. Внешний HTML/text
  export, публичный/неподдерживаемый/без контекста → статичный безопасный
  placeholder без `projectId`, записей, заголовков и без fetch. #133 проверяет,
  различимы ли эти случаи; если нет — privacy-first fallback: placeholder/inert
  блок, а не сериализация или запрос приватных данных.

### FSD-размещение

- `entities/calendar-entry` — типизированные query/data-контракты и нейтральные
  display-данные записи.
- Мутационные сценарии и формы — в feature-слое.
- Точка входа `TopbarMenu` текущей Page — в `widgets/topbar`; виджет
  импортирует мутационный feature/entities/shared (вниз по слоям), а сценарий
  assign/change/remove остаётся в feature-слое.
- Композиция маршрута/полного экрана — в app/pages/widgets.
- Editor-виджет может импортировать features/entities/shared, но не соседний
  календарный виджет.
- Переиспользуемый календарный UI — ниже обеих интеграций; точное место
  адаптера библиотеки/кастомной BlockNote-интеграции решает #133.
- Циклы срезов одного слоя запрещены.
- Локация этой спеки в entity сама по себе не требует держать всю реализацию
  внутри entity.

### Инварианты

- Заголовок всегда `Page.title`.
- В первом релизе у Page максимум одна календарная дата — одна date-only дата,
  не диапазон: нет `start`/`end`, времени суток и timezone.
- Иерархия Page не влияет на календарные даты: родительская и каждая дочерняя
  Page планируются независимо; перемещение Page не меняет её календарную дату.
- Проект никогда не персистится в блоке.
- Месяц экрана — в URL; месяц блока — локально на инстанс.
- Server state — Query, черновики — RHF/local, UI — Zustand, документ — Yjs.
- `from`/`to` диапазона — видимая месячная сетка (до 6 недель, включая дни
  соседних месяцев), а не только календарные 28–31 день месяца.
- Viewer read-only; права не определяются пробным запросом/`403`.
- Placeholder/inert-блок не делает fetch и не несёт приватных данных.
- Календарный доменный контракт не зависит от библиотеки.

## Поведение

1. Экран грузит проекты и (после резолва `projectId`) записи за видимую
   месячную сетку (`[from, to)`, до 6 недель, с днями соседних месяцев).
2. Состояния: loading, empty, error + retry, forbidden, unavailable, invalid
   URL / нет проекта, read-only viewer.
3. Клик по дню создаёт Page на дату в корне проекта (`parentId = null`); форма
   заголовка — правила Page. `clientRequestId` минтится один раз на намерение
   создать и переиспользуется при повторных попытках (retry) той же формы —
   без второго create.
4. Карточка открывает `/app/[pageId]`; форма меняет/снимает дату.
5. `TopbarMenu` текущей Page даёт «Назначить дату» для Page без даты и смену/
   снятие даты для Page с датой; аффорданс только у `owner`/`editor` (#136).
6. prev/next/today меняют `month` в URL; back/forward восстанавливают вид из
   URL.
7. Viewer видит сетку и карточки, но без мутационных аффордансов.

## Критерии приёмки

- Прямая валидная ссылка `/app/calendar?projectId&month` открывает нужный
  проект и месяц.
- prev/next/today и back/forward согласованы с URL.
- Создание, перенос и снятие даты видны без перезагрузки; Page при снятии
  сохраняется.
- Viewer не видит мутационных аффордансов.
- Действие «Назначить дату» и смена/снятие доступны из `TopbarMenu` текущей
  Page для `owner`/`editor` и отсутствуют у `viewer` (#136).
- Даты не зависят от иерархии: назначение/снятие даты не меняет `parentId` и
  структуру дерева, не наследуется потомками и не затрагивает родителя;
  перемещение Page не меняет её дату.
- Несколько блоков на странице не влияют на месяцы друг друга.
- При одинаковых `projectId` и `[from, to)` экран и встроенный блок показывают
  одни и те же записи после принятой политики Query/refetch (общий кэш и
  одинаковые ключи диапазона), включая карточки соседних месяцев.
- В окружениях с разными timezone дата записи не сдвигается.

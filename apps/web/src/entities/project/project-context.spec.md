## Цель

Дать приватной зоне `/app` один разрешённый проектный контекст: пользователь
видит доступные проекты и текущий проект, осознанно переключается между ними,
а дерево страниц и корневое создание всегда работают в одном и том же проекте.
Контекст переживает reload и back/forward и не подменяется первым проектом,
если явный контекст невалиден или недоступен.

## Вне scope

- Ручной UI создания, переименования и удаления проектов; membership, инвайты,
  роли и приглашения (#164/#168).
- Поведение корзины, restore, поиска и их состояний (#128/#129); #172 только
  передаёт им проектный контекст ссылкой.
- Удаление навигации и связанные с ней изменения (#170).
- Производительность и число запросов (#171). «Запрос не отправляется» ниже
  означает корректность контекста (нельзя создать/показать данные другого
  проекта), а не оптимизацию.
- Изменения API, БД, ts-rest-контрактов `packages/shared` и backend ACL.
- Переезд проекта в путь `/app/[pageId]` или смена маршрута страницы.
- Редактор, Yjs-контент и его состояние.
- Содержимое экрана настроек.

## Термины

- **Page-контекст** — проект из серверных метаданных открытой страницы на
  `/app/[pageId]`.
- **Явный URL-контекст** — `projectId` в query-параметрах экрана без открытой
  Page: `/app`, `/app/calendar`, `/app/trash`.
- **Отсутствие контекста** — параметра `projectId` нет и Page-контекст к экрану
  не относится. Это не то же самое, что пустой или неверный `projectId`.
- **Разрешённый контекст** — ровно один проект и источник, из которого он
  получен: `page`, `url` или `fallback`. Пока контекст не разрешён, проекта нет;
  «первый проект по умолчанию» не подставляется.
- **Fallback** — первый доступный проект в серверном порядке. Допустим только
  при отсутствии контекста и только на экранах, чей контракт это разрешает.

## Контракт

Контракт и матрица проверок одобрены человеком 2026-11-08, включая три ранее
Draft-решения в разделе «Решения». Одобрение спеки не означает готовность кода:
тесты проходят независимое AI и человеческое ревью до реализации поведения.

### Приоритет источников

| Маршрут / ситуация                           | Источник `projectId`                          | Fallback и поведение                                                      |
| -------------------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------- |
| `/app/[pageId]`, Page загружена              | `Page.projectId`                              | Нет. `?projectId=` игнорируется и не переопределяет Page                  |
| `/app/[pageId]`, Page грузится               | Контекста ещё нет                             | Нет. Дерево и корневое создание недоступны до ответа Page                 |
| `/app/[pageId]`, Page отсутствует/недоступна | Контекста нет                                 | Нет. Состояние страницы; первый проект не подставляется                   |
| `/app?projectId=<id>`                        | URL                                           | Нет при явном `projectId`; ошибка API видима                              |
| `/app/calendar?projectId=<id>`               | URL                                           | Нет при явном `projectId`; месяц и правила экрана — по его спеке          |
| `/app/trash?projectId=<id>`                  | URL                                           | Нет при явном `projectId`; поведение корзины — по #128                    |
| `/app` без `projectId`                       | Первый доступный проект после загрузки списка | Canonical `replace` в URL; Page не открывается                            |
| `/app/calendar` без `projectId`              | Первый доступный проект после загрузки списка | Да, как уже описано в спеке календаря; canonical `replace`                |
| `/app/trash` без `projectId`                 | Нет                                           | Нет: это chooser-экран #128; первый проект автоматически не подставляется |
| `/app/settings`                              | Нет                                           | Нет: глобальный экран без проектного контекста                            |
| Публичные маршруты `(public)`                | Не относятся к #172                           | Не меняются                                                               |

### Валидность `projectId` в URL

`projectId` обязан быть UUID по контракту Pages/Projects. До разрешения
контекста запросы проекта и страниц не отправляются, fallback не выполняется.

- **Нет параметра** — отсутствие контекста; fallback возможен только по
  контракту экрана.
- **`projectId=` (пустое значение)** — явный, но невалидный контекст: это не
  отсутствие параметра, fallback не выполняется.
- **Повторяющийся параметр с одинаковыми значениями** эквивалентен одному.
- **Повторяющийся параметр с разными значениями** — неоднозначный контекст,
  `invalid`: нельзя молча выбрать одно из значений.
- **Строка не по UUID** — `invalid`: запрос не отправляется, fallback нет,
  пользователь видит явное состояние и может выбрать доступный проект.
- Остальные query-параметры (например `month`) валидируются по спеке своего
  экрана; #172 их не переопределяет.

### Безопасность асинхронного fallback

Везде, где контракт экрана допускает canonical `replace` после загрузки,
перед записью URL проверяется, что исходное навигационное намерение ещё актуально,
текущий маршрут всё ещё допускает этот fallback и явный параметр всё ещё отсутствует.
Поздний ответ не перезаписывает явный выбор, новый маршрут или back/forward;
даже возврат к тому же URL не оживляет старое намерение. Это требование безопасности
контракта, не новый рефакторинг календаря в #172. Для `/app` оно также обязательно.

### Список доступных проектов

- Приходит из `GET /projects` в серверном порядке; клиент не сортирует его по
  алфавиту, дате или локальному состоянию.
- Список — навигационный справочник, а не подтверждение ACL. Устаревший или
  неполный кэш не даёт объявить явный проект недоступным без ответа API:
  для явного `projectId` авторитетны ответы проекта/страниц (`403`/`404`).
  Обратное тоже верно: наличие в списке не гарантирует доступ к страницам —
  `403` от API остаётся окончательным.
- Fallback выбирает первый проект только из успешно загруженного непустого
  списка. При загрузке, ошибке или пустом списке fallback не выполняется.
- Ошибка списка сама по себе не отменяет уже разрешённый Page/URL-контекст:
  переключатель показывает ошибку с повтором, но дерево и корневое создание
  продолжают работать в разрешённом проекте. Если список нужен для fallback,
  его ошибка означает `error` и создания нет.
- Ошибки и недоступность не превращаются в пустой проект, пустой список или
  молчаливую подмену первым доступным проектом.

### Состояния разрешения

| Состояние      | Когда возникает                                                                        | Что видит пользователь                                                      |
| -------------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `pending`      | Грузятся Page-метаданные, список проектов или явный проект                             | Загрузка; дерево и корневое создание недоступны                             |
| `ready`        | Есть ровно один разрешённый проект                                                     | Текущий проект, дерево, доступное корневое создание                         |
| `invalid`      | Контекст пустой, неоднозначный или не проходит проверку UUID                           | «Невалидный проект»; выбор проекта доступен, fallback нет                   |
| `forbidden`    | API вернул `403` для явного проекта                                                    | «Доступ запрещён»; без дерева и создания; доступен выбор доступного проекта |
| `unavailable`  | API вернул `404` для явного проекта (удалён/отсутствует)                               | «Проект недоступен»; без fallback; доступен выбор доступного проекта        |
| `page-missing` | Page не найдена или недоступна на `/app/[pageId]`                                      | Существующее состояние страницы; проект не подставляется                    |
| `error`        | Сеть/`5xx` при загрузке источника проекта (Page, явный проект или список для fallback) | Ошибка с повтором; без fallback и без создания                              |
| `no-projects`  | Список доступных проектов успешно загружен и пуст                                      | Пустое состояние; автосоздание — только по явному клику (ниже)              |
| `chooser`      | `/app/trash` без `projectId` (контракт #128)                                           | Выбор проекта; первый автоматически не выбирается                           |

### Переключатель проекта в Sidebar

- Показывает текущий разрешённый проект и список доступных проектов. Текущий
  проект визуально и программно отмечен как выбранный.
- Использует существующие доступные controls: у триггера понятное доступное имя,
  открытие и выбор доступны с клавиатуры, выбранный пункт объявляется программно;
  закрытие возвращает фокус на триггер по существующему паттерну. При переходе
  фокус не остаётся в размонтированном меню. Ошибки контекста не запрещают
  осознанный выбор доступного проекта из успешно загруженного списка.
- Выбор другого проекта — навигация `router.push('/app?projectId=<id>')`.
  Произвольная Page не открывается, редактор не монтируется.
- Выбор уже текущего проекта — no-op: пользователь остаётся на текущем экране.
- Пунктов создания, переименования, удаления проекта и управления участниками
  в списке нет.
- Пока проекты грузятся — состояние загрузки без подстановки первого проекта.
  Ошибка списка видима и имеет повтор; текущий Page/URL-контекст при этом не
  заменяется, дерево и корневое создание продолжают работать в нём.
- Открыт/закрыт переключатель — локальное UI-состояние. Выбранный `projectId`
  не хранится в Zustand, отдельной Query-записи, localStorage или ином скрытом
  состоянии.

### Дерево и корневое создание

- `PageTree` получает `projectId` только из разрешённого контекста. Своего
  отдельного fallback-правила у дерева нет.
- Корневые кнопки создания используют тот же контекст, что и дерево: проект
  Page, `projectId` экрана или проект, выбранный fallback-правилом.
- У создания нет собственного fallback. На глобальных настройках
  и chooser корзины корневые кнопки недоступны.
  Принятый запрет автосоздания проекта на этих экранах действует независимо.
- Пока контекст `pending`, `invalid`, `forbidden`, `unavailable`, `error` или
  `page-missing`, корневое создание недоступно: запрос не отправляется, страница
  не создаётся в другом проекте. Исключение `no-projects` описано ниже.
- Пустой выбранный проект сохраняется: дерево показывает собственный
  `EmptyState`, корневое создание создаёт страницу именно в нём. Переход к
  первому непустому проекту не выполняется.
- Выбор проекта и родителя вложенного создания (#84/#95) не меняется: проект берётся
  из `projectId` дерева, `parentId` — из строки, fallback на другой проект
  отсутствует. Точка входа доступна только при уже смонтированном дереве с
  разрешённым контекстом.
- Уже отправленная мутация создания сохраняет проект, захваченный при вызове.
  По завершении инвалидируется только кэш этого проекта. Переход, раскрытие
  родителя и тост допустимы только при актуальном исходном навигационном
  намерении: пользователь не ушёл на другой маршрут/страницу, не сменил контекст
  и не выполнил back/forward. Совпадения `projectId` недостаточно; уход и возврат
  не оживляют старое намерение. Иначе текущие URL, проект и дерево не меняются,
  перехода и тоста нет; результат не выдаётся за действие в текущем проекте.
  Это относится и к корневому, и к вложенному созданию, включая ошибки.

#### Автосоздание «Мой проект» — принятое исключение

Единственное исключение из правила «нет контекста — нет создания» сохраняет
текущее поведение:

- Срабатывает только по явному клику пользователя на корневое создание
  страницы, никогда на mount, при загрузке, ошибке или автоматическом выборе.
- Только после успешной загрузки списка доступных проектов и только если он
  пуст. При `pending`, `error` или непустом списке исключение не действует.
- Только при отсутствии явного `projectId` и Page-контекста. Пустой,
  неоднозначный, невалидный или недоступный явный проект исключение не
  включает.
- Только на экранах, где корневое создание доступно: не на `/app/settings`, не
  на chooser-экране `/app/trash` без `projectId`, не при `page-missing`.
- Создаёт «Мой проект» существующим `projectsContract.create`, затем страницу
  в нём; контракт и backend не меняются.
- Не является UI управления проектами: отдельных действий создания,
  переименования и удаления проекта в интерфейсе нет. Проект появляется как следствие
  создания первой страницы.
- Один явный клик задаёт ограниченное намерение «проект, затем Page»; повторный
  клик заблокирован на время цепочки. Если проект создан, его возвращённый ID
  сохраняется в рамках этого намерения и список проектов обновляется/инвалидируется.
  При ошибке Page частичный успех не выдаётся за полный: повтор по явному клику
  создаёт только Page в уже созданном проекте, не второй проект. Это временные
  данные незавершённой операции, не скрытый навигационный выбор проекта.
- Нет автоматического повтора ни одного POST. Если исход создания проекта
  неизвестен (например, сетевой обрыв), нельзя автоматически повторять POST:
  видна ошибка и предлагается обновить список и осознанно выбрать проект.
  После завершения/отмены намерения новый клик оценивает актуальные условия
  заново. Постоянная дедупликация, восстановление через reload и межвкладочные
  гарантии не вводятся.
- Если навигационное намерение устарело, результат уже отправленного запроса
  обновляет исходные кэши (включая список проектов), но не URL/дерево/тост.
  Ещё не отправленный шаг Page автоматически не запускается; уже отправленная
  Page завершается по общим правилам stale-создания. Повтор не возвращает в
  старый проект без нового осознанного выбора.

### Ссылки разделов

| Ссылка    | `href` при разрешённом контексте | Действительно нет контекста (home/chooser/глобальный экран) |
| --------- | -------------------------------- | ----------------------------------------------------------- |
| Домой     | `/app?projectId=<id>`            | `/app`                                                      |
| Календарь | `/app/calendar?projectId=<id>`   | `/app/calendar`                                             |
| Корзина   | `/app/trash?projectId=<id>`      | `/app/trash`                                                |
| Настройки | `/app/settings`                  | `/app/settings`                                             |

- На `/app/[pageId]` контекст ссылок — проект Page; query `projectId` его не
  переопределяет.
- Ожидание/ошибка/отсутствие Page и неразрешённый явный проект — не «действительно
  нет контекста». Пока ожидаемый контекст не разрешён (`pending`, `invalid`,
  `forbidden`, `unavailable`, `page-missing`, `error`), проектные ссылки
  «Календарь»/«Корзина» недоступны или отложены, а не ведут к первому проекту
  через URL без параметра. То же ограничение относится к
  контекстной ссылке «Домой». Переключатель может независимо
  выбрать доступный проект; «Настройки» остаются доступны.
- На экранах без Page контекст ссылок — разрешённый URL-контекст, включая уже
  применённый fallback.
- «Домой», «Календарь» и «Корзина» не открывают произвольную Page.
- «Настройки» — глобальный экран: `projectId` не добавляется. Возврат назад
  восстанавливает контекст из истории, а не из скрытого состояния.
- Reload и back/forward рендерят состояние только из URL и метаданных Page.
  `push` — смена проекта. Canonical `replace` допустим только по контракту
  экрана, без перезаписи поздним ответом нового навигационного намерения.

### Зарезервированные маршруты

`/app`, `/app/calendar`, `/app/trash` и `/app/settings` — статические сегменты
Next.js. Они имеют приоритет над `/app/[pageId]` и не являются Page. Страница
с id, равным зарезервированному слову, по такому URL не открывается; это
принимается, потому что реальные id Page — UUID по контракту `pagesContract`
(path params `z.uuid()`). Новые зарезервированные экраны обязаны явно
определить, проектные они или глобальные, и не трактоваться молча как Page.

## Крайние случаи

Сценарии ниже — одобренный контракт, а не заявление о готовности реализации.

| Случай                                                 | Ожидание                                                                                                                                          |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Два доступных проекта, открыт второй                   | Переключатель показывает оба, текущий — второй; дерево и создание — во втором                                                                     |
| Переключение на другой проект                          | `push` `/app?projectId=<id>`, Page не открывается, дерево меняется на выбранный проект                                                            |
| Reload после переключения                              | Тот же проект из URL; выбранный проект не берётся из памяти                                                                                       |
| Back/forward после переключения                        | URL из истории даёт соответствующий проект; скрытого «текущего проекта» нет                                                                       |
| Выбран пустой проект                                   | `EmptyState` этого проекта; корневое создание создаёт в нём; первый непустой не подставляется                                                     |
| `/app` без `projectId`, есть проекты                   | Первый проект в серверном порядке; canonical `replace`; Page не открывается                                                                       |
| `/app` без `projectId`, проектов нет, клика не было    | Пустое состояние; «Мой проект» не создаётся                                                                                                       |
| `/app` без `projectId`, проектов нет, явный клик       | Создаются «Мой проект» и страница в нём; без клика создания нет                                                                                   |
| `/app` без `projectId`, список проектов упал           | Видимая ошибка; автосоздание не срабатывает                                                                                                       |
| `/app?projectId=` (пусто)                              | `invalid`, как явный неверный контекст; fallback и автосоздание отсутствуют                                                                       |
| `/app?projectId=A&projectId=B`                         | Неоднозначный `invalid`; запрос не отправляется, fallback нет, доступен выбор проекта                                                             |
| `/app?projectId=<невалидная строка>`                   | `invalid`: запрос не отправляется, fallback отсутствует, есть выбор проекта                                                                       |
| `/app?projectId=<валидный, но чужой>`                  | `forbidden`: видимое «доступ запрещён», без дерева и создания в другой проект                                                                     |
| `/app?projectId=<валидный, но удалённый>`              | `unavailable`: видимое «проект недоступен», без fallback                                                                                          |
| `/app/[pageId]?projectId=<другой>`                     | Побеждает `Page.projectId`; query не переопределяет дерево, переключатель и создание                                                              |
| Page грузится, пользователь нажимает корневое создание | Кнопка недоступна, мутация не вызывается, запрос не уходит                                                                                        |
| Page не найдена/недоступна                             | Состояние страницы; проект не подставляется, создание в другой проект недоступно                                                                  |
| Page-метаданные упали по сети                          | Ошибка с повтором; fallback на первый проект отсутствует                                                                                          |
| Список проектов грузится                               | Переключатель в загрузке; при уже разрешённом Page/URL-контексте дерево/создание работают в нём, иначе недоступны; первый проект не подставляется |
| Список проектов упал                                   | Видимая ошибка с повтором; при разрешённом Page/URL-контексте дерево и создание работают в нём; fallback не выполняется                           |
| Смена проекта во время загрузки старого Page           | Поздний ответ старого Page не меняет URL/контекст; данные старого проекта не выдаются за новые                                                    |
| Смена контекста после отправки создания                | Запрос остаётся в захваченном проекте; кэш обновляется только там; перехода в новый проект и дубля нет                                            |
| `/app/trash` без `projectId`                           | Chooser #128: первый проект автоматически не выбирается; ссылка из Sidebar приходит с контекстом                                                  |
| `/app/calendar?projectId=<id>&month=...`               | Календарь открывает указанный проект/месяц; его поведение не меняется                                                                             |
| `/app/settings`                                        | Глобальный экран без контекста; `projectId` не добавляется; корневые кнопки недоступны                                                            |
| `/app/<reserved>` как id Page                          | Открывается статический маршрут, не Page; зарезервированные имена не поддерживаются как id                                                        |
| Проект выбран, затем пропал из доступных               | Авторитетен ответ API (`403`/`404`); автоматический переход на первый проект не выполняется                                                       |

## Взаимодействия

| Слой            | Что хранит                                                                        |
| --------------- | --------------------------------------------------------------------------------- |
| URL             | `pageId` на `/app/[pageId]`; `projectId` на `/app`, `/app/calendar`, `/app/trash` |
| TanStack Query  | список доступных проектов, метаданные Page; выбранный контекст не дублируется     |
| Zustand         | только UI: открыт ли переключатель/сайдбар/drawer                                 |
| Yjs + BlockNote | только контент редактора; проект в контенте не хранится                           |

- ADR-002: URL-first. На Page-маршруте проект выводится из Page, на экранах без
  Page — из `projectId`. Уточнение зафиксировано в ADR-002/ADR-005.
- ADR-005: `projectId` на экранах без Page — навигационный контекст в URL, не
  server state и не UI state. Reload и back/forward восстанавливают его из URL
  и метаданных Page.
- ADR-008: `entities/project` даёт список и детали проекта, `entities/page` —
  метаданные Page; ни одна сущность не импортирует соседнюю. Разрешённый
  контекст компонуется выше по слоям, а потребители получают готовый
  `projectId`. Спека задаёт поведение, а не размещение кода; конкретное место
  композиции выбирается при реализации в рамках ADR-008. Соседние
  features/widgets друг друга не импортируют.
- Потребители одного контекста: `widgets/sidebar`, `features/create-page`,
  `widgets/page-trash`, календарь. Поведение restore/search/trash остаётся в
  #128.
- ADR-013: спека одобрена; тесты проходят независимое AI и человеческое ревью
  до реализации. Автор тестового прохода: OpenAI (GPT-6.1 Sol), 2026-11-08.
- `packages/shared` и backend не меняются: используются существующие
  `projectsContract`, `Project`, `Page` и `pagesContract`.

## Решения

### Принято человеком (2026-11-08)

1. **Page metadata — источник истины на `/app/[pageId]`.** `?projectId=` не
   переопределяет проект открытой страницы.
2. **На экранах без Page проект задаётся URL.** `/app`, `/app/calendar`,
   `/app/trash` читают разрешённый `projectId` из URL; `/app/settings` —
   глобальный экран.
3. **Переключатель Sidebar ведёт на `/app?projectId=<id>`** и не открывает
   произвольную Page.
4. **Автосоздание «Мой проект» сохраняется как ограниченное исключение** —
   условия в разделе «Автосоздание «Мой проект»». Открытый вопрос этим закрыт.
5. **Fallback только при отсутствии явного контекста и по контракту экрана.**
   Пустой, неверный или недоступный явный контекст не заменяется первым проектом.
6. **Границы состояния и история.** Навигационный выбор не дублируется в Query,
   Zustand или localStorage; reload и back/forward восстанавливают его из URL
   и метаданных Page, список и метаданные остаются server state в Query.

### Дополнительно принято человеком (2026-11-08)

1. **Canonical `replace` для `/app` без контекста.** После загрузки списка
   первый доступный проект записывается в URL через `replace`, как уже делает
   календарь. URL становится единственным источником контекста, запись истории
   не добавляется.
2. **Корневое создание недоступно на `/app/settings` и chooser-экране
   `/app/trash` без `projectId`.** Первый проект там молча не выбирается;
   автосоздание «Мой проект» на эти экраны не распространяется.
3. **«Домой» несёт контекст.** Ссылка ведёт на `/app?projectId=<id>`, чтобы
   переход из Page в домашний экран не менял проект на первый; без контекста —
   `/app`.

## Открытые вопросы

Материальных открытых вопросов нет. Спека в целом и три ранее Draft-решения
одобрены человеком 2026-11-08. Следующий gate — независимое AI и человеческое
ревью тестов; до него реализация поведения запрещена.

# Spec: Настройки профиля — имя

**Статус:** Draft
**Автор:** daria-z
**Дата:** 2026-10-28
**Связанные:** [ADR-004](../../../../../docs/adr/004-data-fetching.md), [ADR-005](../../../../../docs/adr/005-state-management.md), issue #125, [apps/api/src/users/users.spec.md](../../../../api/src/users/users.spec.md) (BE-контракт, issue #124, уже смёржен), issue #19 (пункт «Настройки» в сайдбаре сейчас заглушка)

## Цель

Пользователь открывает настройки из сайдбара, видит свой email и текущее
имя, меняет имя и сохраняет — новое имя сразу видно в блоке пользователя
сайдбара, без перезагрузки страницы.

## Контракт

Route: `/app/settings` — `apps/web/src/app/app/settings/page.tsx`, Client
Component. В проекте нет отдельного FSD-слоя `pages`: файл рендерится
прямо в `app/app/layout.tsx` (общие Sidebar/Topbar не дублируются), по
образцу `app/app/[pageId]/page.tsx`.

API (BE готов, [users.spec.md](../../../../api/src/users/users.spec.md)):

```
PATCH /users/:userId   body: { username }   → 200 { user } | 400 | 401 | 403 | 404
```

`username` — `usernameSchema` из `@noto/shared/api`: `trim`, длина
`USERNAME_MIN_LENGTH`..`USERNAME_MAX_LENGTH` (1..80).

```tsx
// features/update-username/api/use-update-username.ts
export function useUpdateUsername(): UseMutationResult<User, ApiClientError, string>;
```

- `mutationFn` вызывает `apiClient.users.update({ params: { userId }, body: { username } })`,
  `userId` — id текущего пользователя из `useCurrentUser()` (`entities/user`),
  не проп: хук всегда работает со своим профилем.
- Успех → `invalidateQueries({ queryKey: userKeys.current() })` (это
  единственный релевантный ключ: `useCurrentUser` читает `/auth/me`,
  отдельного ключа под `/users/me` в проекте нет) + `toast.success`.
- Ошибка → `toast.error`; введённое значение не сбрасывается — отвечает
  форма, не хук (RHF-состояние поля живёт независимо от мутации).

Форма — `apps/web/src/features/update-username/ui/update-username-form.tsx`,
React Hook Form + `zodResolver(usernameSchema)` на поле `username`. Email —
read-only текст, не часть формы: не валидируется и не отправляется.

## Поведение

1. Переход на `/app/settings` — пункт «Настройки» в сайдбаре
   (`widgets/sidebar/ui/sidebar.tsx`). Сейчас это `SidebarNavItem` без
   `href`, `disabled=true` по умолчанию (issue #19, заглушка). Делаем его
   рабочей ссылкой — либо `SidebarNavItem` получает вариант, рендерящий
   `Link`, либо пункт выносится как прямой `Link`, как уже сделано для
   «Домой» (минуя `SidebarNavItem`). Остальные пункты сайдбара не меняются.
2. На странице — `useCurrentUser()` отдаёт email и текущий `username`.
   Пока данные грузятся — состояние загрузки (как в `SidebarUserBlock`),
   формы ещё нет.
3. Email — read-only текст. `username` — поле формы, предзаполнено
   текущим значением (`null` → пустая строка).
4. Кнопка «Сохранить» — disabled на время мутации, повторный клик не
   шлёт второй запрос (как в `useCreatePage`).
5. Успех — `toast.success`, `userKeys.current()` инвалидируется →
   `SidebarUserBlock` и сама форма получают новое значение без reload.
   Форма остаётся на экране, редиректа нет.
6. Ошибка — `toast.error`, значение в поле не сбрасывается — можно
   скорректировать и повторить.
7. `SidebarUserBlock` (`widgets/sidebar/ui/sidebar-user-block.tsx`) —
   показывает `user.username`, если задан, иначе `user.email` (как
   сейчас). Буква в аватаре-фолбэке — первый символ того же значения.

## Крайние случаи

| Случай                                                      | Ожидание                                                                 |
| ------------------------------------------------------------ | ------------------------------------------------------------------------- |
| Пустое имя / только пробелы                                   | Ошибка валидации на клиенте (`zodResolver`) до отправки, запрос не шлётся |
| Имя длиннее 80 символов                                       | Ошибка валидации на клиенте, запрос не шлётся                           |
| `400 VALIDATION_ERROR` от сервера (рассинхрон с клиентской валидацией) | `toast.error`, значение в поле сохраняется                      |
| `403 FORBIDDEN`                                                | `toast.error` — в норме не ожидаемый путь: `userId` всегда свой, берётся из сессии |
| `401`                                                          | Ничего не делаем — `shared/api/client.ts` сам обновляет сессию или уводит на `/login` |
| Двойной клик «Сохранить»                                       | Один запрос — кнопка заблокирована на время мутации                      |
| Повторная отправка того же значения                           | Запрос всё равно уходит — клиент не сравнивает со старым значением       |
| Reload после успешного сохранения                              | Имя сохранено на сервере — новое монтирование `useCurrentUser` отдаёт актуальное значение |
| У пользователя нет имени (`username: null`)                   | Поле формы пустое; `SidebarUserBlock` показывает email, как сейчас       |
| Ошибка первоначальной загрузки профиля (`useCurrentUser` упал) | Вместо формы — сообщение об ошибке и кнопка «Повторить» (`refetch`); заголовок страницы остаётся |

## Взаимодействия

Состояние по матрице [ADR-005](../../../../../docs/adr/005-state-management.md):
email/username — server state (TanStack Query, `entities/user`); черновик
поля формы — локальный state React Hook Form, не Zustand; переход на
`/app/settings` — URL.

`SidebarUserBlock` и форма настроек читают один и тот же
`useCurrentUser()` / `userKeys.current()` — инвалидация после мутации
обновляет оба места одним запросом, без ручной синхронизации.

Тест-первым (ADR-013) — логика `useUpdateUsername` (тело запроса,
инвалидация, обработка `403`/`401`/сетевой ошибки) по образцу
`use-create-page.test.tsx`. Вёрстка формы и включение пункта сайдбара —
регрессия вместе с кодом, без теста (это файловая разметка, не логика).

## Открытые вопросы

- Как технически включать пункт «Настройки» в сайдбаре — вариант `href`
  в `SidebarNavItem` или прямой `Link` по образцу «Домой» — решается в
  реализации, не меняет наблюдаемое поведение.
- Текст placeholder для пустого имени в форме — финальная формулировка на
  усмотрение реализации.

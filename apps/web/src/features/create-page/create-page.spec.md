# Spec: Создание страницы

**Статус:** Draft
**Автор:** daria-z
**Дата:** 2026-08-23
**Связанные:** [ADR-004](../../../../../docs/adr/004-data-fetching.md), [ADR-011](../../../../../docs/adr/011-authorization-acl.md), issue #54 (вторая половина — дерево описано в [page-tree.spec.md](../../widgets/sidebar/page-tree.spec.md)), issue #84 (кнопка «+» в строке дерева), issue #172 и [project-context.spec.md](../../entities/project/project-context.spec.md) (единый проектный контекст)

## Цель

Пользователь создаёт страницу — в корне проекта или внутри существующей — и
сразу попадает в неё.

## Вне scope

- Дерево страниц и его рендер — [page-tree.spec.md](../../widgets/sidebar/page-tree.spec.md).
- Переименование (в том числе замена «Без названия» на настоящий заголовок),
  перемещение, удаление страницы.
- Редактор контента: страница создаётся с пустым `content`.

## Контракт

```tsx
// features/create-page/api/use-create-page.ts
// `projectId` — расширение #84 к текущему no-arg хуку; параметр опционален.
export function useCreatePage(
  projectId?: string,
): UseMutationResult<Page, ApiClientError, CreatePageInput>;
// CreatePageInput = { title?: string; parentId?: string | null }
```

**Предусловие.** Ключи `pages.list(projectId)` — целевые после #53; в `main`
сейчас `pageKeys.byProject`. Как и PageTree, мержится после #53.

- Запрос — `POST /projects/:projectId/pages` через `apiClient` (ts-rest,
  контракт `pagesContract.create` в `@noto/shared`). Ответ `201 { page }`.
- `title` при создании не вводится: подставляется «Без названия». Формы нет —
  страница создаётся одним кликом, переименование живёт в редакторе (FE-P4).
  Ограничение 1..200 (`PAGE_TITLE_MIN_LENGTH`/`PAGE_TITLE_MAX_LENGTH` из
  `@noto/shared`) остаётся в силе для будущего переименования.
- `parentId` не передан → страница в корне проекта.
- **Активный проект и фолбэк.** Корневые точки входа без аргумента используют
  единый разрешённый проектный контекст (#172, [project-context.spec.md](../../entities/project/project-context.spec.md)):
  без собственного выбора первого проекта. Источники и допустимость fallback
  определяет контракт текущего маршрута, не эта фича. Пока контекст не
  разрешён (`pending`, `invalid`, `forbidden`, `unavailable`, `error`,
  `page-missing`), корневое создание недоступно: запрос не отправляется,
  страница не создаётся в другом проекте. Пустой выбранный проект не
  заменяется первым.
- С явным `projectId` (вложенная точка входа #84) страница создаётся только в
  этом проекте и **не** фолбэкает на другой: при недоступных метаданных
  открытой страницы фолбэк создал бы страницу в чужом проекте. Вложенная точка
  входа доступна только при уже смонтированном дереве с разрешённым контекстом.
- **Проектов нет вовсе — ограниченное исключение.** Существующее автосоздание
  «Мой проект» сохраняется: только по явному клику на корневое создание, после
  успешной загрузки списка и только если он пуст; только при отсутствии явного
  `projectId` и Page-контекста; не на `/app/settings` и не на chooser-экране
  `/app/trash` без `projectId`. Сначала создаётся «Мой проект» существующим
  `projectsContract.create`, затем страница в нём. На mount, при загрузке,
  ошибке списка и недоступном контексте создания нет; UI управления проектами
  не появляется. Полный контракт —
  [project-context.spec.md](../../entities/project/project-context.spec.md),
  «Автосоздание «Мой проект»».
- Ответ приходит конвертом `{ page }`; хук разворачивает его и резолвится
  самой `Page`, наружу конверт не протекает.
- После успеха: `invalidateQueries(pages.list(page.projectId))` — только кэш
  проекта, захваченного при вызове. Переход `router.push('/app/<page.id>')`
  выполняется, только если исходное навигационное намерение ещё актуально:
  пользователь не ушёл на другой маршрут/страницу, не сменил контекст и не
  выполнил back/forward (совпадения одного `projectId` недостаточно).
  Иначе поздний ответ не меняет URL и дерево,
  не уводит в старый проект и не создаёт дубль.
  Тост и раскрытие родителя также допускаются только при актуальном исходном
  намерении, включая ошибку. Если проект автосоздан, но Page упала, ID проекта
  сохраняется в текущем намерении, список проектов обновляется/инвалидируется;
  явный повтор создаёт только Page в нём. Двойной клик не запускает вторую
  цепочку; неопределённый исход POST проекта не повторяется автоматически.
  Полные границы намерения и позднего завершения — в #172.

## Поведение

1. «Новая страница» в корне — существующая `SidebarNewPageButton`.
2. Проект без страниц — та же мутация из кнопки «Создать страницу» в слоте
   `action` у `EmptyState` дерева
   ([page-tree.spec.md](../../widgets/sidebar/page-tree.spec.md)): кнопку
   отдаёт эта фича, рендерит виджет.

   Тексты кнопок различаются: постоянный пункт сайдбара — «Новая
   страница» (ярлык действия в меню), на пустом экране — «Создать
   страницу». Мутация за обеими одна.

3. Успех → список страниц исходного проекта инвалидируется; переход на новую
   страницу — только при актуальном исходном навигационном намерении (см. контракт).
4. Пока мутация в полёте — кнопка заблокирована, повторный клик запроса не шлёт.
5. «+» в строке дерева (#84) — вложенная точка входа: хук вызывается с явным
   `projectId` дерева, `parentId` = id строки; создаётся та же сущность с
   пустым `content` и заголовком «Без названия».
6. Пока вложенная мутация в полёте, все «+» дерева заблокированы — одна
   вложенная мутация за раз. Меню «…» остаются рабочими; корневые кнопки
   создания не блокируются.
7. Успех вложенного создания: список страниц исходного проекта инвалидируется;
   только при актуальном исходном навигационном намерении родитель раскрывается
   (повторное раскрытие — no-op), затем переход на новую страницу.
8. Ошибка вложенного создания: тост только при актуальном исходном намерении,
   строка не раскрывается, перехода нет;
   после завершения все «+» дерева снова доступны.

## Крайние случаи

Во всех строках ниже тост, переход и раскрытие после ответа подчиняются
проверке исходного навигационного намерения из контракта; исходный кэш
обновляется и при устаревшем намерении.

| Случай                                               | Ожидание                                                                                                                                                      |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `400 VALIDATION_ERROR` от сервера                    | Toast с ошибкой; вводить нечего, значит и терять нечего — это признак рассинхрона с контрактом                                                                |
| `403 FORBIDDEN` (роль `viewer`)                      | Toast «Недостаточно прав»                                                                                                                                     |
| `404` (проект удалён)                                | Toast с ошибкой, редиректа нет                                                                                                                                |
| `401`                                                | Ничего не делаем: `shared/api/client.ts` сам обновляет сессию или уводит на `/login`                                                                          |
| Двойной клик по кнопке                               | Один запрос — кнопка заблокирована на время мутации                                                                                                           |
| Несколько страниц подряд                             | Все называются «Без названия»; различать их можно только по порядку, пока нет переименования                                                                  |
| Двойной клик по «+» строки                           | Один запрос; пока он в полёте, все «+» дерева заблокированы                                                                                                   |
| «+» в двух строках одновременно                      | Второй клик не отправляет запрос: одна вложенная мутация за раз, все «+» дерева заблокированы                                                                 |
| Ошибка вложенного создания                           | Тост, родитель не раскрывается, перехода нет; после завершения «+» снова доступны                                                                             |
| Корневые кнопки при вложенной мутации                | Не блокируются; блокируются только «+» дерева                                                                                                                 |
| Нет метаданных открытой страницы, клик по «+» строки | Проект берётся из `projectId` дерева; фолбэка на другой проект нет                                                                                            |
| `/app?projectId=B`, корневое создание                | Страница создаётся в `B`, не в первом доступном проекте                                                                                                       |
| Явный `projectId` пустого проекта                    | Страница создаётся в нём; первый непустой проект не подставляется                                                                                             |
| Контекст ещё грузится, клик по корневой кнопке       | Кнопка недоступна, `createPage` не вызывается, запрос не уходит                                                                                               |
| Явный проект невалиден или недоступен                | Видимое состояние; корневое создание недоступно; запроса в другой проект нет                                                                                  |
| `/app` без `projectId`, проектов нет, клик           | Создаются «Мой проект» и страница в нём; без клика создания нет                                                                                               |
| `/app` без `projectId`, проектов нет, клика не было  | «Мой проект» не создаётся; пустое состояние                                                                                                                   |
| Список проектов упал, клик по корневому созданию     | Видимая ошибка; автосоздание не срабатывает; страница не создаётся                                                                                            |
| `projectId=` пустой или повторяющийся с разными ID   | `invalid`; корневое создание недоступно; автосоздание не срабатывает                                                                                          |
| Смена проекта после отправки создания                | Запрос остаётся в захваченном проекте; кэш обновляется только там; в новый проект не перенаправляется, перехода на созданную страницу нет, дубль не создаётся |

## Взаимодействия

Состояние по матрице [ADR-005](../../../../../docs/adr/005-state-management.md):
мутация и инвалидация — TanStack Query, переход на созданную страницу — URL.
Формы нет, поэтому и черновика в локальном state нет.

ACL ([ADR-011](../../../../../docs/adr/011-authorization-acl.md)): роль
пользователя на проекте API не возвращает, поэтому кнопки создания показываем
всем и обрабатываем `403`. Кнопка «+» в строке — без изменений: видна всем,
`403` даёт тот же тост.

Логика «+» (явный `projectId`, `parentId`, одна вложенная мутация за раз,
раскрытие родителя, ошибка без перехода) — предмет тестов, которые пишут по
этой спеке и ревьюят до кода. Внешний вид кнопки (hover/focus,
`pointer: coarse`, фиксированная ширина слота) — вёрстка: проверяется вручную,
unit-тестами не дублируется.

## Открытые вопросы

Автосоздание «Мой проект» сохраняется как ограниченное
исключение (см. «Контракт»). UI создания, переименования и удаления проектов
остаётся вне scope #172; если он понадобится, это отдельная задача.
В #172 ещё ждут подтверждения canonical `replace` на `/app`, недоступность
корневых кнопок в настройках/chooser и контекстная ссылка «Домой»; эта спека
не вводит независимый fallback до их согласования. Запрет автосоздания проекта
в настройках/chooser уже принят и не зависит от решения о кнопках.

Точка входа «внутри родителя» закрыта в #84: слот действий строки уже есть,
кнопку «+» в него кладёт `PageTree` (поведение — здесь и в
[page-tree.spec.md](../../widgets/sidebar/page-tree.spec.md)).

# Продуктовые требования

Источник: ТЗ проекта Noto (учебный командный проект).

## О продукте

**Тип продукта:** продвинутая система ведения заметок, документации и проектов.

**Цель:** создать лёгкую, современную альтернативу Notion для ведения проектов, работы с календарём, документации и конспектов.

**Результат:** открытый GitHub-проект + развёрнутое приложение на сервере.

> На первый взгляд проект может выглядеть простым, но объём работ рассчитан на несколько месяцев командной разработки.

## Обязательная функциональность

- Аутентификация и авторизация
- Создание проектов с группировкой страниц
- Вложенность страниц и заметок
- Поиск и фильтры
- Корзина
- Работа с изображениями, видео, календарём, todo-списками
- Комментарии в редакторе
- Совместное редактирование (Websockets + Socket.io)
- ИИ для быстрой генерации контента (любое API)
- История изменений
- Публикация статей из заметок:
  - SEO-настройка для поисковых систем
  - Приватность (скрыть статью, обновить)
- Личный кабинет и настройки
- Интеграция с Telegram-ботом (уведомления, связь с календарём)

## Продуктовый фокус

Реализовать базовый функционал для работы с заметками и конспектами, ведением документации. Полноценный редактор с возможностью:

- вести проекты;
- заполнять календарь;
- строить вложенную структуру;
- использовать ИИ;
- вести учёт изменений;
- realtime-редактирование от нескольких пользователей;
- публикация статей.

## Начальные этапы разработки (из ТЗ)

1. Формирование команды, распределение ролей, первый созвон
2. Инициализация и базовая конфигурация проектов
3. Создание досок для работы, декомпозиция на параллельные блоки
4. Перекрёстное код-ревью (не только тимлид)
5. Еженедельный отчёт в пятницу (gap даже если маленький)

## Цель обучения

Задача — не сделать «как можно больше», а **научиться новому** и получить командный опыт: основы, инфраструктура, ИИ, realtime, prod-практики.

# ADR-002: Маршруты, домены и навигация

**Статус:** Accepted  
**Дата:** 2026-07-14

## Контекст

Приложение совмещает приватную рабочую зону (редактор, проекты) и публичный контент (SEO-статьи). Нужна понятная структура URL, совместимая с шарингом страниц и SEO.

## Решение

### Домены

| Домен | Назначение | Когда |
|-------|------------|-------|
| `noto.app` | Основное приложение + минимальный лендинг | Сейчас |
| `blog.noto.app` | Публичные SEO-статьи | Позже (см. [RFC-004](../rfc/004-blog-subdomain.md)) |

### Маршруты на `noto.app`

| Путь | Зона | Описание |
|------|------|----------|
| `/` | public | Минимальный лендинг |
| `/login`, `/register` | public | Страницы аутентификации |
| `/app/*` | private | Авторизованная зона |
| `/app/[pageId]` | private | Текущая страница (основная навигация) |

После успешного логина пользователь перенаправляется в `/app`.

### Навигация — по аналогии с Notion

- **URL-first для страниц:** при переходе по сайдбару URL всегда меняется (`/app/[pageId]`)
- **Проект не в URL:** проект/workspace выводится из данных страницы (родитель, breadcrumbs)
- Работают deep links, «назад/вперёд» в браузере, шаринг ссылок на страницу

### Next.js route groups

```
apps/web/src/app/
├── (public)/           # лендинг, auth, позже — превью статей
│   ├── page.tsx        # /
│   ├── login/
│   └── register/
└── app/                # приватная зона
    ├── layout.tsx      # QueryClientProvider, auth guard
    └── [pageId]/
        └── page.tsx
```

### Публичные статьи (текущая фаза)

До выноса на `blog.noto.app` — в том же Next.js app, в route group `(public)`. Рендер через RSC (см. [ADR-004](./004-data-fetching.md)).

## Альтернативы

| Вариант | Почему отклонён |
|---------|-----------------|
| `/app/projects/[projectId]/pages/[pageId]` | Длинные URL; Notion так не делает |
| Проект в URL, страница в Zustand | Нет deep links на страницу |
| `app.noto.app` для приложения | Лишний поддомен на старте |
| `/[slug]` на корне для статей | Конфликт с маршрутами приложения |

## Последствия

- Middleware защищает только `/app/*` (см. [ADR-003](./003-authentication.md))
- Сайдбар и дерево страниц синхронизируются с `[pageId]` из URL
- Миграция на `blog.noto.app` потребует отдельного RFC и не блокирует старт

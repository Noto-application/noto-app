# ADR-014: Адаптивность / responsive-стратегия

**Статус:** Accepted
**Дата:** 2026-08-10

## Контекст

Адаптивность нигде не была зафиксирована; вопрос всплыл на UI-kit
([RFC-009](../rfc/009-responsive-strategy.md)). Обсудили на командном созвоне и
приняли решение.

## Решение

- **Noto адаптивный.** Явные цели — **mobile ↔ desktop**. Планшет **не
  проектируется отдельно**: попадает в диапазон между брейкпоинтами
  автоматически.
- **Брейкпоинты — дефолтные Tailwind** (`sm/md/lg/xl/2xl`). Своя шкала не
  вводится.
- **Хардкод размеров запрещён** — верстаем через брейкпоинты и токены (перегибы
  вроде `w-[180px]` у `Select` пересмотреть).
- **Редактор:** полноценный на desktop/tablet; на mobile — чтение + лёгкое
  редактирование (детали — на этапе редактора).
- **Типографика:** текущая шкала (`--text-*`, фиксированные px) остаётся для MVP;
  fluid-типографика — отложено.

## Последствия

- **FE-3 ([#19](https://github.com/Noto-application/noto-app/issues/19)):** сайдбар/
  топбар сворачиваются в drawer под `lg`.
- Компоненты UI-kit тянутся по контейнеру, ширины — через брейкпоинты, не
  фиксированные.
- Мобилка в скоупе — задачи фронта учитывают узкие экраны с самого начала.

## Отклонённые альтернативы

| Вариант                    | Почему нет                                                       |
| -------------------------- | ---------------------------------------------------------------- |
| Только desktop             | Мобилка нужна для чтения/быстрых правок; есть ресурс (4-й фронт) |
| Планшет как отдельная цель | Избыточно — покрывается диапазоном `md/lg`                       |
| Своя шкала брейкпоинтов    | Преждевременно; дефолтов Tailwind достаточно                     |
| Fluid-типографика сейчас   | Полиш, не MVP                                                    |

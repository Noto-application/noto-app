# ADR-013: Spec-Driven + Test-First разработка

**Статус:** Accepted
**Дата:** 2026-08-10

## Контекст

В проекте активно используются AI-ассистенты; их слабое место — додумывание
деталей, которых нет в задаче. Подход прорабатывался в
[RFC-008](../rfc/008-spec-driven-development.md), обкатан на auth и Projects.
Команда приняла его как обязательный процесс.

## Решение

**Порядок для значимой фичи: spec → тесты → код.**

- **Spec** описывает поведение и контракт (не реализацию), живёт **рядом с кодом**
  (`<name>.spec.md` в папке модуля/слайса); `docs/specs/` — реестр и
  кросс-модульные спеки.
- **Тесты** пишутся по спеке (крайние случаи → тест-кейсы), затем код закрывает
  тесты.

### Градация по масштабу

| Масштаб                   | Процесс                                        |
| ------------------------- | ---------------------------------------------- |
| Значимая фича             | Spec → тесты → код; spec ревьюят перед стартом |
| Обычный модуль / эндпоинт | Тест-первым; spec — пара строк в описании PR   |
| Багфикс, вёрстка, мелочь  | Тест где осмысленно; spec не нужен             |

### Где test-first не догматичен

- **UI/вёрстка** — тесты на логику (хуки, стор), не на разметку; визуал —
  Storybook + Playwright постфактум.
- **Realtime/Yjs** — поведение эмерджентное; тесты интеграционные после спайка.
- **Внешние интеграции** (OpenAI, S3, TG-бот) — сначала спайк, тесты на обёртку
  потом.

### Против overfitting (обязательно)

**Тест ревьюит человек до написания кода** — либо тест и код пишут разные проходы
/ разные люди. Иначе один агент за проход подгонит тест под код (тавтология).

### Guideline «в обкатке»: split-people

Когда тесты и код пишут **разные люди**: тест-автор пишет **чёрный-ящик e2e**
(контракт поведения, не диктует внутренний дизайн), код-автор пишет unit под свой
код. Пилотируется на Projects (#30); закрепим правилом, если приживётся.

## Последствия

- Contract-first ([ADR-012](./012-api-contract.md)) — часть потока: контракт уже
  спека API, дальше тест на хендлер → реализация.
- Раздел «Взаимодействия» в спеке сверяется с матрицей состояния
  ([ADR-005](./005-state-management.md)).
- Процесс кратко закреплён в [AGENTS.md](../../AGENTS.md).

## Отклонённые альтернативы

| Вариант                           | Почему нет                                        |
| --------------------------------- | ------------------------------------------------- |
| Code-first, тесты потом           | AI додумывает; тесты подгоняются под готовый код  |
| Полный spec+test на каждую мелочь | Команда не выдержит; отсюда градация по масштабу  |
| Spec как пересказ реализации      | Дублирование работы; spec — про поведение, не код |

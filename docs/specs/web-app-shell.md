## Цель

Каркас приватной рабочей зоны `/app`: пользователь видит дерево своих проектов
и страниц в сайдбаре, ориентируется по пути до страницы в топбаре, и любой
переход к странице отражается в URL — так что на неё можно дать прямую
ссылку или вернуться кнопкой «назад».

## Вне scope

- Сам редактор страницы (контент `[pageId]`) — отдельная задача.
- Присутствие пользователей в реальном времени (кто ещё сейчас смотрит
  страницу) — не реализовано, только статичный визуал аватаров.
- Логика Входящих и Календаря — пункты-заглушки в сайдбаре, без функционала.
- Поиск (⌘K) — заглушка/модалка без реальной логики.
- Мутации проектов/страниц (создание, переименование, удаление, права) —
  read-only каркас на фикстурах. Backend для проектов есть (issue #27,
  PR #30), для Pages/прав — нет; в любом случае вне scope этой задачи.
- Публикация страницы — кнопка «Опубликовать» в топбаре визуальная заглушка.

## Контракт

**Роуты** (ADR-002):
```
apps/web/src/app/app/layout.tsx        — приватный layout: QueryProvider (PR #44)
apps/web/src/app/app/[pageId]/page.tsx — текущая страница
```
`QueryProvider` — обвязка TanStack Query (`shared/api/query-provider.tsx`,
PR #44), без которой хуки `useProjects()`/`useProject()` не будут работать
ни в одном вложенном компоненте. Проверка авторизации живёт не в layout, а в
`apps/web/src/proxy.ts` (Next.js middleware, матчер `/app/:path*`, PR #44) —
редиректит на `/login` раньше, чем layout вообще начнёт рендериться.

Проект не участвует в URL — выводится из данных страницы (родитель/путь до страницы).

**`entities/project`** — read-only хуки `useProjects()`, `useProject(id)`
поверх фикстур. Тип `Project` — реэкспорт из `@noto/shared` (уже есть в коде,
PR #30): `id`, `name`, `createdAt`, `updatedAt` (без `deletedAt` — публичное
представление намеренно его не показывает). Паттерн реэкспорта — как в уже
существующем `entities/user` (PR #44).

**`entities/page`** — тип `Page` (`id`, `title`, `projectId`, `parentId`) +
аналогичные read-only хуки поверх фикстур. Backend-спеки для Pages нет, но
поле называется `parentId`, а не `parentPageId`, заранее — под будущую
backend-модель Pages (issue #45), чтобы не переименовывать при переходе на
реальный API.

**`widgets/sidebar`** — переключатель рабочего пространства (заглушка, одно
рабочее пространство), поиск (⌘K, заглушка), Входящие/Календарь
(пункты-заглушки), дерево проектов (раскрываемое, проект → вложенные
страницы), корзина (заглушка списка), настройки (ссылка-заглушка), «Новая
страница» (заглушка), блок пользователя.

**`widgets/topbar`** — хлебные крошки (многоуровневые), аватары присутствия
(статичный список), «Опубликовать» (заглушка), «…»-меню (`DropdownMenu`),
под `lg` — кнопка открытия сайдбара (на мобильных сайдбар превращается в
`drawer`).

**`useSidebarStore` (Zustand, ADR-005 — только UI-состояние)**:
```ts
type SidebarState = {
  expandedProjectIds: Set<string>; // v1: только в памяти (in-memory), не сохраняется между сессиями
  toggleProject: (projectId: string) => void;
  isDrawerOpen: boolean; // актуально только < lg
  setDrawerOpen: (open: boolean) => void;
};
```
Не хранит `pageId`/`projectId` (те — в URL), не дублирует
`entities/project`/`entities/page`.

## Поведение

1. `/app` без `pageId` → редирект на первую страницу первого проекта; нет
   проектов/страниц — пустое состояние (см. «Крайние случаи»).
2. Клик по странице в дереве → `router.push('/app/[pageId]')`. Открытая
   страница не хранится в Zustand (ADR-005) — только в URL.
3. Раскрытие/сворачивание узла дерева → Zustand, не отражается в URL.
4. Топбар пересчитывает путь до страницы из `pageId`, поднимаясь по дереву
   до проекта.
5. Пока `entities/project`/`entities/page` в состоянии загрузки
   (`isLoading`) — `Skeleton`.
6. Под `lg` (ADR-014) сайдбар превращается в `drawer`: скрыт по умолчанию,
   открывается кнопкой в топбаре, закрывается по клику вне зоны или выбору
   страницы. Топбар остаётся на экране в обычном виде.
7. Заход на `/app/[pageId]` не по клику в дереве (прямая ссылка, refresh) →
   сайдбар автораскрывает путь от проекта до страницы (по `pageId` +
   структуре дерева, без сохранения между сессиями); уже раскрытые узлы не
   сворачивает.

## Крайние случаи

| Случай                                                | Ожидание                                                              |
| ------------------------------------------------------ | ------------------------------------------------------------------------ |
| `pageId` в URL не существует                          | Страница-заглушка «не найдено» (не `EmptyState`); сайдбар/топбар не падают |
| Нет ни одного проекта                                 | `EmptyState` в сайдбаре вместо дерева                                    |
| Проект есть, страниц в нём нет                        | Пустой список, не ошибка                                                 |
| Глубокое дерево (путь до страницы)                    | v1: без обрезки, полный путь + `overflow-x: auto` при переполнении       |
| Прямая ссылка/refresh на вложенную страницу           | Автораскрытие пути (Поведение п.7)                                       |
| Узкий экран, `< lg`                                   | Сайдбар — `drawer`, открывается кнопкой в топбаре (ADR-014)              |

## Взаимодействия

- **URL** — навигация по дереву (ADR-002, матрица ADR-005).
- **TanStack Query** — `entities/project`/`entities/page`, сейчас на
  фикстурах; переключение на реальный API — второй шаг этой же задачи (см.
  «Решения»).
- **Zustand** — раскрытые узлы дерева, открыт ли сайдбар как `drawer` на
  мобильных (`useSidebarStore`).
- **`shared/ui` (FE-2)** — весь набор доступен: `Button`, `Avatar` (PR-1),
  `DropdownMenu`/`Skeleton`/`EmptyState` (PR-2, PR #34) — оба смёржены.

## Решения

- Сайдбар как мобильный `drawer` (ADR-014) — в scope issue #19, не
  отдельная задача (Поведение п.6).
- Раскрытые узлы дерева — не сохраняются между сессиями в v1, только
  автораскрытие активной страницы (Поведение п.7; полноценное сохранение —
  «Открытые вопросы» №2).
- Кнопка «Новая страница» в `EmptyState` — заглушка, ничего не делает.
- 404 по `pageId` — отдельная страница-заглушка, не `EmptyState`.
- Фикстуры → реальный `/projects` API — второй шаг этой же задачи/PR, после
  того как `projects.spec.md` перейдёт из Draft в Accepted (финальный статус
  спеки по процессу проекта, ADR-013) — backend уже смёржен, PR #30.
- Путь до страницы — без обрезки в v1, `overflow-x: auto` при переполнении
  (умная обрезка — «Открытые вопросы» №1).
- **Единая семантика «не найдено» на моках и на реальном API.**
  `getProject`/`getPage` возвращают `undefined` для неизвестного id, не
  бросают исключение. При переходе на реальный API (второй шаг) обработчик
  404 должен маппиться туда же в `undefined`, а не пробрасываться как
  ошибка — иначе консьюмеры (сайдбар, путь до страницы), уже завязанные на
  `undefined`, сломаются при переключении на реальные данные.

## Открытые вопросы

1. **Обрезка пути до страницы.** В v1 нет. Нужна ли «умная» обрезка позже
   (сколько уровней, кликабельность «…», вид по DS) — решить на ревью.
2. **Сохранение дерева между сессиями.** В v1 его нет. Если понадобится —
   `Set` не сериализуется дефолтным `JSON.stringify` у Zustand `persist`,
   нужен кастомный `storage` — решить на ревью.

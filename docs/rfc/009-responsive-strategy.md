# RFC-009: Адаптивность / responsive-стратегия

**Статус:** Superseded by [ADR-014](../adr/014-responsive-strategy.md)
**Дата:** 2026-08-10

> Обсуждено на созвоне, решение вынесено в
> [ADR-014](../adr/014-responsive-strategy.md). Этот RFC оставлен как история.

## Контекст

Команда хочет сделать Noto адаптивным, но это нигде не зафиксировано и не
обсуждалось предметно. Всплыло по ходу работы над UI-kit (issue #32,
dropdown-menu): у `Select`-триггера уже есть жёстко заданная ширина
(`w-[180px]`), остальные атомы UI-kit тянутся по контейнеру сами по себе,
без осознанного решения. Ни `docs/product-requirements.md`, ни RFC-007
(MVP scope) вопрос устройств/экранов не поднимают.

## Вопросы для обсуждения

- Нужна ли адаптивность в MVP (RFC-007), или это Phase 2+
- Целевые устройства: только desktop, desktop + tablet, или включая mobile
- Брейкпоинты — своя шкала или дефолтные Tailwind
- Поведение сайдбара/топбара на узких экранах — пересекается с issue #19
  (FE-3 · App shell)
- Типографика: текущая шкала (`--text-*` в globals.css) вся в фиксированных
  px, без fluid-типографики — пересматривать или нет

## Следующие шаги

1. Командное обсуждение: нужна ли адаптивность и в каком объёме для MVP
2. Зафиксировать решение — Accepted здесь, либо явное «не в MVP» в RFC-007
3. Если да — решить брейкпоинты, завести ADR, отразить в issue #19
